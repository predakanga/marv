1	# CS-034: Always Use Colon on Trailing Parameters — COMPLETED
2	
3	**Source:** GitHub issue #10
4	**Scope:** Core
5	**Complexity:** Small
6	**Breaking changes:** None — wire format change is backwards-compatible with all IRC parsers
7	**Status:** Completed
8	
9	---
10	
11	## Problem
12	
13	`IrcSerializer.Serialize()` currently omits the `:` prefix on the last
14	parameter when it's not strictly required (i.e. when the parameter
15	contains no spaces, doesn't start with `:`, and is non-empty). While
16	this is technically correct per RFC 1459, some IRC software does not
17	handle the colon-less form correctly, causing interoperability issues.
18	
19	## Changes
20	
21	### 1. Always prefix the last parameter with `:`
22	
23	In `IrcSerializer.Serialize()` (lines 55–61), replace the conditional
24	colon logic:
25	
26	```csharp
27	// Last parameter needs trailing prefix if it contains spaces,
28	// starts with ':', or is empty
29	if (i == message.Parameters.Count - 1 &&
30	    (param.Contains(' ') || param.StartsWith(':') || param.Length == 0))
31	{
32	    sb.Append(':');
33	}
34	```
35	
36	With an unconditional colon on the last parameter:
37	
38	```csharp
39	if (i == message.Parameters.Count - 1)
40	{
41	    sb.Append(':');
42	}
43	```
44	
45	This is a simplification — the code becomes shorter and the behaviour
46	more predictable.
47	
48	### 2. Update serializer tests
49	
50	Update `IrcSerializerTests` to expect the colon on all trailing
51	parameters. The "simple params without colon" test case will need
52	updating to expect e.g. `"FOO bar :baz"` instead of `"FOO bar baz"`.
53	
54	The round-trip test should continue to pass since the parser already
55	handles both forms.
56	
57	## Design decisions
58	
59	- **Always-colon, not configurable:** Adding a toggle between strict
60	  and compatible modes would add complexity for negligible benefit.
61	  Always using the colon is universally compatible — every IRC parser
62	  must handle it. There is no practical reason to prefer the colon-less
63	  form.
64	- **No parser changes needed:** `IrcParser` already handles both forms
65	  correctly. Only the serializer output changes.
66	
67	## Testing
68	
69	- Unit test: verify all serialized messages with parameters include `:`
70	  before the last parameter.
71	- Unit test: round-trip (parse → serialize → parse) continues to
72	  produce equivalent messages.
73	- Manual test: connect to an IRC server and verify normal operation
74	  (JOIN, PRIVMSG, NICK, etc. all work correctly).
75	
76	## Impact
77	
78	- **Plugin API:** No changes. Plugins interact with `IrcMessage` objects,
79	  not raw wire format.
80	- **DX:** None — this is an internal protocol detail.
81	- **Risk:** Very low. The colon-prefixed form is the more common
82	  convention across IRC implementations and is guaranteed to be parsed
83	  correctly by all compliant software.

3	namespace Marv.Core.Protocol;

5	/// <summary>
6	/// Serializes <see cref="IrcMessage"/> instances to IRC wire format.
7	/// Handles tag value escaping per the IRCv3 message-tags spec.
8	/// </summary>
9	public static class IrcSerializer
10	{
11	    /// <summary>
12	    /// Serializes an <see cref="IrcMessage"/> to wire format (without trailing CR-LF).
13	    /// </summary>
14	    public static string Serialize(IrcMessage message)
15	    {
16	        var sb = new StringBuilder(512);
17	
18	        // Tags
19	        if (message.Tags.Count > 0)
20	        {
21	            sb.Append('@');
22	            var first = true;
23	            foreach (var (key, value) in message.Tags)
24	            {
25	                if (!first) sb.Append(';');
26	                first = false;
27	
28	                sb.Append(key);
29	                if (value is not null && value.Length > 0)
30	                {
31	                    sb.Append('=');
32	                    EscapeTagValue(sb, value);
33	                }
34	            }
35	            sb.Append(' ');
36	        }
37	
38	        // Source
39	        if (message.Source is not null)
40	        {
41	            sb.Append(':');
42	            sb.Append(message.Source);
43	            sb.Append(' ');
44	        }
45	
46	        // Command
47	        sb.Append(message.Command);
48	
49	        // Parameters
50	        for (var i = 0; i < message.Parameters.Count; i++)
51	        {
52	            sb.Append(' ');
53	            var param = message.Parameters[i];
54	
55	            if (i == message.Parameters.Count - 1)
56	            {
57	                sb.Append(':');
58	            }
59	
60	            sb.Append(param);
61	        }
62	
63	        return sb.ToString();
64	    }
65	
66	    /// <summary>
67	    /// Escapes a tag value per the IRCv3 message-tags spec:
68	    /// ; → \:  space → \s  \ → \\  CR → \r  LF → \n
69	    /// </summary>
70	    internal static void EscapeTagValue(StringBuilder sb, string value)
71	    {
72	        foreach (var c in value)
73	        {
74	            switch (c)
75	            {
76	                case ';': sb.Append("\\:"); break;
77	                case ' ': sb.Append("\\s"); break;
78	                case '\\': sb.Append("\\\\"); break;
79	                case '\r': sb.Append("\\r"); break;
80	                case '\n': sb.Append("\\n"); break;
81	                default: sb.Append(c); break;
82	            }
83	        }
84	    }
85	}
