1	# CS-027: Idiomatic Configuration Loading
2	
3	**Source:** GitHub issue #4
4	**Scope:** Host
5	**Complexity:** Small-Medium
6	**Breaking changes:** None — existing `marv.json` and `MARV_` env var behaviour preserved
7	**Status:** Pending
8	
9	---
10	
11	## Problem
12	
13	The host application (`Program.cs`) calls `builder.Configuration.Sources.Clear()`
14	and rebuilds the configuration stack from scratch, discarding the default .NET
15	providers (`appsettings.json`, `appsettings.{Environment}.json`, etc.). This is
16	surprising for users familiar with .NET conventions. Additionally,
17	`ConfigurationOptions` serves two purposes — generating CLI option definitions
18	and extracting overrides via `GetOverrides` — when it should only do the former.
19	
20	## Changes
21	
22	### 1. Preserve the default configuration stack
23	
24	Stop calling `builder.Configuration.Sources.Clear()`. Instead, walk the existing
25	`IConfigurationBuilder.Sources` and replace any `JsonConfigurationSource`
26	instances with JSON5 equivalents so that `appsettings.json` gains JSON5 comment
27	support for free.
28	
29	### 2. Add `marv.json` as a higher-priority source
30	
31	After the default stack is preserved, add `marv.json` (and any `--config`
32	override) as a JSON5 source layered on top, so Marv-specific settings take
33	precedence over `appsettings.json` defaults.
34	
35	### 3. Use the host builder's environment variable prefix
36	
37	Remove the manual `builder.Configuration.AddEnvironmentVariables("MARV_")` call.
38	Instead, configure the host builder's default environment variable provider with
39	the `MARV_` prefix via `builder.Configuration.AddEnvironmentVariables("MARV_")`
40	— or, if the default host builder already provides a way to set the prefix,
41	use that.
42	
43	> **Note:** The default `Host.CreateApplicationBuilder()` adds an unprefixed
44	> env var provider. If there is no built-in way to configure its prefix, keep
45	> the explicit `AddEnvironmentVariables("MARV_")` call but do not clear the
46	> default provider — let both coexist so that standard .NET env vars (e.g.
47	> `ASPNETCORE_ENVIRONMENT`) still work.
48	
49	### 4. Create a `CommandLineConfigurationProvider`
50	
51	Replace `ConfigurationOptions.GetOverrides()` and the `AddInMemoryCollection`
52	approach with a custom `IConfigurationProvider` that wraps the
53	`System.CommandLine.ParseResult`. This provider will:
54	
55	- Iterate the `Entry` list and extract explicitly-set CLI values.
56	- Present them as configuration keys, maintaining the same precedence (CLI
57	  overrides everything).
58	
59	This simplifies `ConfigurationOptions` to a single responsibility: generating
60	`Option<T>` definitions from `MarvConfiguration` properties.
61	
62	### 5. Remove `GetOverrides` and entry `Apply` methods
63	
64	Once the `CommandLineConfigurationProvider` is in place, remove:
65	
66	- `ConfigurationOptions.GetOverrides(ParseResult)`
67	- The `Apply` method on `Entry` and its subclasses (`ScalarEntry`, `BoolEntry`,
68	  `CollectionEntry`)
69	- The `AddInMemoryCollection` call in `Program.cs`
70	
71	`ConfigurationOptions` retains `Build()`, `All`, and the entry records (for
72	option metadata) but the records no longer need `Apply`.
73	
74	## Design decisions
75	
76	- **Preserve `marv.json` as the default config filename** rather than switching
77	  to `appsettings.json`. The owner confirmed this in issue discussion.
78	- **Layer order** (lowest to highest priority):
79	  1. Default .NET stack (`appsettings.json`, `appsettings.{Environment}.json`)
80	  2. `marv.json` (Marv-specific settings override appsettings defaults)
81	  3. Environment variables (`MARV_` prefix)
82	  4. CLI arguments (via `CommandLineConfigurationProvider`)
83	- **Custom provider over in-memory collection**: the `GetOverrides` +
84	  `AddInMemoryCollection` approach works but gives `ConfigurationOptions` two
85	  responsibilities. A dedicated provider is more idiomatic and single-purpose.
86	
87	## Testing
88	
89	- Unit test: `CommandLineConfigurationProvider` returns correct keys for various
90	  `ParseResult` inputs (scalar, bool, collection).
91	- Unit test: verify config layering precedence — CLI > env vars > marv.json >
92	  appsettings.json.
93	- Unit test: verify that `appsettings.json` with JSON5 comments parses correctly
94	  after the JSON source replacement.
95	- Manual test: run the bot with a combination of `appsettings.json`,
96	  `marv.json`, `MARV_` env vars, and CLI args to confirm precedence.
97	
98	## Impact
99	
100	- **Plugin API:** No changes.
101	- **User-facing:** Users gain `appsettings.json` support. Existing `marv.json`
102	  and `MARV_` env var workflows continue to work.
103	- **Risk:** Low. The configuration stack order is well-defined and testable.
104	  Existing users who only use `marv.json` + CLI args see no difference.

11	/// Auto-generates System.CommandLine <see cref="Option"/> instances from
12	/// <see cref="MarvConfiguration"/> properties, and extracts CLI overrides
13	/// into a config-compatible dictionary after parsing.
14	/// </summary>

16	{
17	    private abstract record Entry(Option Option)
18	    {
19	        /// <summary>
20	        /// If the option was provided on the command line, writes the value(s) into the overrides dictionary
21	        /// using .NET configuration keys (e.g. "Server", "Channels:0").
22	        /// </summary>
23	        public abstract void Apply(ParseResult result, Dictionary<string, string?> overrides);
24	    }
25	
26	    private sealed record ScalarEntry<T>(Option<T> TypedOption, string ConfigKey) : Entry(TypedOption)
27	    {
28	        public override void Apply(ParseResult result, Dictionary<string, string?> overrides)
29	        {
30	            if (result.GetResult(TypedOption) is null) return;
31	            var value = result.GetValue(TypedOption);
32	            if (value is not null)
33	                overrides[ConfigKey] = value.ToString();
34	        }
35	    }
36	
37	    private sealed record BoolEntry(Option<bool?> TypedOption, string ConfigKey) : Entry(TypedOption)
38	    {
39	        public override void Apply(ParseResult result, Dictionary<string, string?> overrides)
40	        {
41	            if (result.GetResult(TypedOption) is null) return;
42	            var value = result.GetValue(TypedOption);
43	            if (value is not null)
44	                overrides[ConfigKey] = value.Value.ToString();
45	        }
46	    }
47	
48	    private sealed record CollectionEntry(Option<string[]> TypedOption, string ConfigKey) : Entry(TypedOption)
49	    {
50	        public override void Apply(ParseResult result, Dictionary<string, string?> overrides)
51	        {
52	            if (result.GetResult(TypedOption) is null) return;
53	            var values = result.GetValue(TypedOption);
54	            if (values is null) return;
55	            for (var i = 0; i < values.Length; i++)
56	                overrides[$"{ConfigKey}:{i}"] = values[i];
57	        }
58	    }
59	
60	    private static readonly List<Entry> Entries = Build();
61	
62	    /// <summary>All generated CLI options, ready to add to a <see cref="RootCommand"/>.</summary>
63	    public static IEnumerable<Option> All => Entries.Select(e => e.Option);
64	
65	    /// <summary>
66	    /// Inspects the <see cref="ParseResult"/> and returns a dictionary of configuration
67	    /// overrides for any options the user explicitly provided on the command line.
68	    /// </summary>
69	    public static Dictionary<string, string?> GetOverrides(ParseResult result)
70	    {
71	        var overrides = new Dictionary<string, string?>();
72	        foreach (var entry in Entries)
73	            entry.Apply(result, overrides);
74	        return overrides;
75	    }

77	    private static List<Entry> Build()
78	    {
79	        var entries = new List<Entry>();
80	
81	        foreach (var prop in typeof(MarvConfiguration).GetProperties(BindingFlags.Public | BindingFlags.Instance))
82	        {
83	            var cliName = $"--{ToKebabCase(prop.Name)}";
84	            var description = prop.GetCustomAttribute<DescriptionAttribute>()?.Description ?? "";
85	            var propType = prop.PropertyType;
86	            var underlying = Nullable.GetUnderlyingType(propType) ?? propType;
87	
88	            if (propType == typeof(bool))
89	            {
90	                var opt = new Option<bool?>(cliName) { Description = description };
91	                entries.Add(new BoolEntry(opt, prop.Name));
92	            }
93	            else if (underlying == typeof(int))
94	            {
95	                var opt = new Option<int?>(cliName) { Description = description };
96	                entries.Add(new ScalarEntry<int?>(opt, prop.Name));
97	            }
98	            else if (underlying == typeof(double))
99	            {
100	                var opt = new Option<double?>(cliName) { Description = description };
101	                entries.Add(new ScalarEntry<double?>(opt, prop.Name));
102	            }
103	            else if (underlying == typeof(string))
104	            {
105	                var opt = new Option<string?>(cliName) { Description = description };
106	                entries.Add(new ScalarEntry<string?>(opt, prop.Name));
107	            }
108	            else if (underlying.IsEnum)
109	            {
110	                AddEnumEntry(entries, underlying, cliName, description, prop.Name);
111	            }
112	            else if (propType == typeof(string[]))
113	            {
114	                var opt = new Option<string[]>(cliName)
115	                {
116	                    Description = description,
117	                    AllowMultipleArgumentsPerToken = true
118	                };
119	                entries.Add(new CollectionEntry(opt, prop.Name));
120	            }
121	        }
122	
123	        return entries;
124	    }

126	    /// <summary>
127	    /// Adds a <see cref="ScalarEntry{T}"/> for a nullable enum type via reflection,
128	    /// so new enum properties on <see cref="MarvConfiguration"/> are handled automatically.
129	    /// </summary>

135	        opt.Description = description;

138	        entries.Add((Entry)Activator.CreateInstance(entryType, opt, configKey)!);
139	    }

151	            }
152	            else

155	            }
156	        }
157	        return sb.ToString();
158	    }

using System.CommandLine.Parsing;
using System.ComponentModel;
using System.Reflection;
using System.Text;
using Marv.Core;
using Microsoft.Extensions.Configuration;

namespace Marv;

/// <summary>
/// An <see cref="IConfigurationProvider"/> that extracts explicitly-provided CLI
/// values from a <see cref="ParseResult"/> and presents them as configuration keys.
/// Only options the user actually specified on the command line appear; absent
/// options produce no keys, so lower-priority sources are not overwritten.
/// </summary>
internal sealed class CommandLineConfigurationProvider : ConfigurationProvider
{
    private readonly ParseResult _parseResult;

    public CommandLineConfigurationProvider(CommandLineConfigurationSource source)
    {
        _parseResult = source.ParseResult;
    }

    /// <inheritdoc />
    public override void Load()
    {
        var data = new Dictionary<string, string?>(StringComparer.OrdinalIgnoreCase);

        foreach (var prop in typeof(MarvConfiguration).GetProperties(BindingFlags.Public | BindingFlags.Instance))
        {
            var cliName = $"--{ToKebabCase(prop.Name)}";
            var propType = prop.PropertyType;
            var underlying = Nullable.GetUnderlyingType(propType) ?? propType;

            if (propType == typeof(string[]))
            {
                ExtractCollection(data, cliName, prop.Name);
            }
            else if (propType == typeof(bool))
            {
                ExtractBool(data, cliName, prop.Name);
            }
            else
            {
                ExtractScalar(data, cliName, prop.Name);
            }
        }

        Data = data;
    }

    private void ExtractScalar(Dictionary<string, string?> data, string cliName, string configKey)
    {
        var option = FindOption(cliName);
        if (option is null || _parseResult.GetResult(option) is null)
            return;

        var value = _parseResult.GetValue<object?>(option);
        if (value is not null)
            data[configKey] = value.ToString();
    }

    private void ExtractBool(Dictionary<string, string?> data, string cliName, string configKey)
    {
        var option = FindOption(cliName);
        if (option is null || _parseResult.GetResult(option) is null)
            return;

        var value = _parseResult.GetValue<bool?>(option);
        if (value is not null)
            data[configKey] = value.Value.ToString();
    }

    private void ExtractCollection(Dictionary<string, string?> data, string cliName, string configKey)
    {
        var option = FindOption(cliName);
        if (option is null || _parseResult.GetResult(option) is null)
            return;

        var values = _parseResult.GetValue<string[]>(option);
        if (values is null) return;
        for (var i = 0; i < values.Length; i++)
            data[$"{configKey}:{i}"] = values[i];
    }

    private Option? FindOption(string name)
    {
        foreach (var symbol in _parseResult.RootCommandResult.Command.Options)
        {
            if (symbol.Name == name)
                return symbol;
        }
        return null;
    }

    private static string ToKebabCase(string pascalCase)
    {
        var sb = new StringBuilder();
        for (var i = 0; i < pascalCase.Length; i++)
        {
            var c = pascalCase[i];
            if (char.IsUpper(c))
            {
                if (i > 0) sb.Append('-');
                sb.Append(char.ToLowerInvariant(c));
            }
            else
            {
                sb.Append(c);
            }
        }
        return sb.ToString();
    }
}

/// path, optional, and reloadOnChange settings.

{

    {

/// <summary>

/// Supports .json, .json5, .yaml/.yml, and .xml formats.
/// </summary>
static void AddConfigFile(IConfigurationBuilder config, string path, bool required)
{
    var extension = Path.GetExtension(path).ToLowerInvariant();

    switch (extension)
    {
        case ".json" or ".json5":
            config.AddJson5File(path, optional: !required, reloadOnChange: true);
            break;
        case ".yaml" or ".yml":
            config.AddYamlFile(path, optional: !required, reloadOnChange: true);
            break;
        case ".xml":
            config.AddXmlFile(path, optional: !required, reloadOnChange: true);
            break;
        default:
            throw new InvalidOperationException(
                $"Unsupported configuration file format: '{extension}'. " +
                "Supported formats: .json, .json5, .yaml, .yml, .xml");
    }

1	# CS-028: Plugin Loading Integration Tests
2	
3	**Source:** GitHub issue #3
4	**Scope:** Tests
5	**Complexity:** Medium
6	**Breaking changes:** None
7	**Status:** Pending
8	
9	---
10	
11	## Problem
12	
13	Plugin loading has proven fragile, particularly around interactions with
14	`PublishSingleFile`, `SelfContained`, and the `MetadataLoadContext`-based
15	inspection code. Existing unit tests cover individual components
16	(`PluginDiscovery`, `PluginDependencySorter`, `PluginManager` instantiation)
17	but no tests exercise the full pipeline against published artifacts. Regressions
18	in the interaction between phases go undetected until a release is built.
19	
20	## Changes
21	
22	### 1. Add a published-output test fixture
23	
24	Create a test fixture class (e.g. `PublishedOutputFixture`) that:
25	
26	- Runs `dotnet publish` on the Marv host project and plugin projects to a
27	  temporary directory, producing the same artifact layout as `make publish`.
28	- Exposes the output directory paths (host output dir, plugin dir) to tests.
29	- Caches the build output for the test run (build once, run many tests).
30	
31	The fixture should use an idiomatic xUnit approach (`IAsyncLifetime` or
32	`ICollectionFixture<T>`) rather than shelling out to `make`, so it works
33	correctly in CI without requiring Make.
34	
35	### 2. Metadata scanning tests
36	
37	Tests that exercise `PluginMetadataScanner.ScanDirectories()` against the
38	published plugin DLLs:
39	
40	- Verify that all expected plugins are discovered (Greet, CannedResponses,
41	  Auth, AuthConsumer, Moderation).
42	- Verify plugin names are correctly extracted (from `[PluginName]` attributes
43	  and class name conventions).
44	- Verify that non-plugin DLLs in the plugin directory are ignored.
45	
46	### 3. Full pipeline tests
47	
48	Tests that exercise the complete loading pipeline:
49	
50	- `PluginMetadataScanner.ScanDirectories()` → `ResolveRequestedPlugins()` →
51	  `PluginManager.DiscoverAndRegister()` → `InstantiatePlugins()`.
52	- Verify assembly resolution works correctly in a published context (where
53	  assembly probing differs from development builds).
54	- Verify dependency sorting: Auth must load before AuthConsumer.
55	- Verify service registration: plugins' `ConfigureServices` methods are called.
56	- Verify `[PluginConfig]` configuration binding works end-to-end with an
57	  in-memory `IConfiguration`.
58	
59	### 4. Error case tests
60	
61	- Missing plugin assembly: verify clear error message.
62	- Plugin with unsatisfied dependency: verify error message names the missing
63	  dependency.
64	- Assembly that is not a valid plugin: verify it is skipped gracefully.
65	
66	### 5. Test organisation
67	
68	- Tests live in `tests/Marv.Core.Tests/Integration/PluginLoading/`.
69	- Tagged with `[Trait("Category", "Integration")]` so they are included in
70	  `make test-integration` and excluded from `make test`.
71	- Shared fixture via `[CollectionDefinition]` / `[Collection]` to avoid
72	  rebuilding published output per test class.
73	
74	## Design decisions
75	
76	- **Published artifacts, not development builds**: The owner confirmed that
77	  several past failures only manifested in published output due to
78	  `PublishSingleFile` / `SelfContained` interactions with `MetadataLoadContext`.
79	  Testing against development build output would miss these regressions.
80	- **xUnit fixture over Makefile**: Using `dotnet publish` directly from the
81	  fixture is more portable and CI-friendly than depending on Make.
82	- **No IRC server needed**: These tests only exercise the plugin loading
83	  pipeline, not IRC connectivity. They need built assemblies and a
84	  `ServiceCollection`, not a running IRC server.
85	
86	## Testing
87	
88	- All new tests are themselves the deliverable.
89	- Verify tests pass with `make test-integration` (or `dotnet test --filter
90	  "Category=Integration"`).
91	- Verify tests fail correctly when a plugin DLL is removed from the published
92	  output.
93	
94	## Impact
95	
96	- **Plugin API:** No changes.
97	- **DX:** Developers gain confidence that plugin loading works end-to-end in
98	  published artifacts. CI catches regressions that unit tests miss.
99	- **Risk:** Very low. Test-only change; no production code modified.
