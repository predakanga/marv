2	
3	This document describes Marv's assembly structure, internal layering,
4	async/threading model, plugin loading, and inter-plugin service system.
5	
6	---
7	
8	## Assembly Structure
9	
10	```
11	Marv.sln
12	├── src/
13	│   ├── Marv.App/            # CLI host application
14	│   ├── Marv.Core/           # Core library
15	│   └── plugins/
16	│       ├── Marv.Plugins.Ping/       # Example: simple ping/pong
17	│       ├── Marv.Plugins.Auth/       # Example: auth service provider
18	│       └── Marv.Plugins.Greet/      # Example: consumes auth service
19	├── tests/
20	│   ├── Marv.Core.Tests/
21	│   └── Marv.Plugins.Tests/
22	└── docs/

25	### Marv.App
26	
27	The CLI host application. A thin shell that delegates to the core.
28	
29	Responsibilities:
30	
31	- Parse command-line arguments (using `System.CommandLine` 2.x)
32	- Read configuration from files, environment variables, and CLI args
33	  (in ascending priority order)
34	- Initialize logging (`Microsoft.Extensions.Logging` with console and
35	  file sinks)
36	- Call `services.AddMarv(configuration)` to delegate plugin loading,
37	  dependency sorting, service registration, and bot setup to the core
38	- Run the hosted service and handle graceful shutdown (Ctrl+C /
39	  SIGTERM)
40	
41	The app does **not** perform plugin discovery, DI wiring, or bot
42	orchestration itself — that is the core's responsibility. The app
43	builds the `IHostBuilder`, registers configuration and logging, calls
44	the core's extension method, and runs.
45	
46	This assembly references `Marv.Core` and the .NET hosting/DI packages.
47	It does not reference any plugin assemblies directly — plugins are
48	loaded at runtime.
49	
50	### Marv.Core
51	
52	The core library. Contains everything a plugin author needs to
53	reference at compile time, and everything the host needs to run the
54	bot. This is the only assembly that plugin projects reference.
55	
56	Responsibilities:
57	
58	- IRC message parsing and serialization
59	- TCP/TLS connection management
60	- IRCv3 capability negotiation and SASL authentication
61	- Protocol-level message handling (PING/PONG, CTCP VERSION/PING/TIME)
62	- Rate-limited message sending
63	- Channel/user/mode state tracking
64	- The `IPlugin` interface and `MarvPlugin` convenience base class
65	- Plugin attributes and lifecycle management
66	- Event types and the event dispatch system
67	- The `IBot` facade interface
68	- Plugin discovery, dependency sorting, and lifecycle management
69	- The `IServiceCollection` extension method (`AddMarv`) that wires
70	  everything together
71	
72	### Plugin Assemblies
73	
74	Each plugin is a separate assembly (class library) that references
75	`Marv.Core`. A plugin assembly contains:
76	
77	- Exactly one plugin class implementing `IPlugin` (typically via
78	  `MarvPlugin`)
79	- Optional configuration record/class tagged with
80	  `[PluginConfig(Section = "Name")]`
81	- Optional service interfaces (or these may live in a separate
82	  contracts assembly shared between provider and consumer)
83	- Optional service implementations
84	- Optional handler group classes
85	
86	Plugin assemblies are built as DLLs and placed in a known directory.
87	The host discovers them at startup via the configured plugin paths.

91	## Internal Layering (Marv.Core)
92	
93	The core library is organized into layers, each building on the one
94	below it. Higher layers depend on lower layers; lower layers never
95	reference higher layers.
96	
97	```
98	┌─────────────────────────────────────────┐
99	│            Plugin System                │  Plugin loading, lifecycle,
100	│   IPlugin, MarvPlugin, attributes       │  event dispatch
101	├─────────────────────────────────────────┤
102	│            Bot / Message Processor      │  IBot — high-level API
103	│   Send messages, query state,           │  exposed to plugins.
104	│   PING/PONG, CAP, state updates,        │  Protocol handling and
105	│   event fan-out to plugin tasks         │  state management.
106	├─────────────────────────────────────────┤
107	│            State Tracking               │  Channels, users, modes,
108	│   IChannelStore, IUserStore             │  ISUPPORT parameters
109	├─────────────────────────────────────────┤
110	│            Connection                   │  TCP/TLS, reconnection,
111	│   IIrcConnection                        │  rate limiting
112	├─────────────────────────────────────────┤
113	│            Protocol                     │  IrcMessage parsing,
114	│   IrcParser, IrcSerializer              │  serialization, tags,
115	│                                         │  case mapping
116	└─────────────────────────────────────────┘
117	```
118	
119	### Protocol Layer
120	
121	- `IrcMessage`: Immutable record representing a parsed IRC message
122	  (tags, source, command, parameters). Used for both inbound and
123	  outbound messages — the structure is identical (tags, command,
124	  parameters), with the only difference being that inbound messages
125	  have a source prefix and outbound messages do not. Keeping a single
126	  type avoids conversion overhead and lets plugins inspect/transform
127	  messages uniformly.
128	- `IrcParser`: Parses raw bytes/strings into `IrcMessage` instances.
129	  Handles tag value escaping, multi-space separation, empty trailing
130	  parameters, and source prefix parsing. Validated against
131	  ircdocs/parser-tests vectors.
132	- `IrcSerializer`: Serializes `IrcMessage` back to wire format.
133	- `CaseMapping`: Implements RFC 1459, strict-RFC 1459, and ASCII case
134	  mapping for nick/channel comparison. The active mapping is read from
135	  ISUPPORT and can change at runtime.
136	
137	### Connection Layer
138	
139	- `IIrcConnection`: Abstracts the TCP/TLS connection. Provides a
140	  `ChannelReader<IrcMessage>` for inbound messages and accepts
141	  outbound messages via a `ChannelWriter<IrcMessage>`.
142	- Implements rate limiting on outbound messages using a token bucket
143	  algorithm to prevent excess flood disconnections.
144	- Handles reconnection with exponential backoff.
145	- UTF-8 encoding with graceful handling of invalid sequences.
146	
147	The connection layer is a pure transport — it does not interpret
148	message content. PING/PONG handling, CAP negotiation, and all other
149	protocol-level logic live in the message processor (bot layer) where
150	they have access to state and can be tested without a network
151	connection.
152	
153	### State Tracking
154	
155	- `IChannelStore`: Maintains the set of channels the bot is in, each
156	  with its topic, modes, and member list (including per-user prefixes
157	  and join times).
158	- `IUserStore`: Maintains known users (nick, user, host, account, away
159	  status). Updated from NAMES, WHO, JOIN, PART, QUIT, NICK, CHGHOST,
160	  ACCOUNT, AWAY, SETNAME messages.
161	- `IModeParser`: Parses MODE changes using the server's CHANMODES and
162	  PREFIX from ISUPPORT to correctly handle type A/B/C/D modes.
163	- All comparisons use the server's advertised CASEMAPPING.
164	
165	State stores are written by the message processor task and read by
166	plugin tasks. `IUser` and `IChannel` objects are mutable — the
167	message processor updates properties in place. Only the message
168	processor writes, so no write contention exists.
169	
170	Thread safety for concurrent reads is achieved through:
171	
172	- Atomic individual property reads (reference type fields in .NET)
173	- `ConcurrentDictionary` for collection-valued properties, ensuring
174	  safe enumeration while the message processor adds/removes entries
175	
176	Cross-property consistency within a single `IUser` or `IChannel` is
177	not guaranteed during a handler — a state change could land between
178	two reads. This is rare in practice, and plugins needing strict
179	consistency can copy values into locals at handler entry. Plugins
180	holding a reference to an `IUser` or `IChannel` see live updates
181	to that object's properties.
182	
183	### Bot / Message Processor
184	
185	- `IBot`: The primary interface plugins interact with. Provides
186	  methods for sending messages, querying channel/user state, and
187	  checking capability availability. See `plugin-api-draft.md` for the
188	  full surface.
189	- The message processor is the central task that reads from the
190	  inbound channel and:
191	  - Handles PING/PONG (responds immediately, not exposed to plugins)
192	  - Handles core CTCP queries (VERSION, PING, TIME) — responds
193	    automatically without exposing host information; only the bot
194	    version string is included. Other CTCP queries are translated
195	    into `CtcpEvent` for plugin handling.
196	  - Drives CAP negotiation and SASL authentication
197	  - Updates state tracking (channels, users, modes)
198	  - Translates raw `IrcMessage` into typed events
199	  - Fans out events to each plugin's individual event channel
200

202	
203	- Plugin discovery, assembly loading, dependency graph construction,

210	## Async / Threading Model
211	
212	Marv uses a small number of long-lived async tasks communicating via
213	`System.Threading.Channels`. Each plugin runs on its own dedicated
214	task, receiving events through its own channel.
215	
216	### Task Structure
217	
218	```
219	                                             ┌──────────────────┐
220	                                          ┌─►│  Plugin A Task   │
221	                                          │  │  Channel<Event>  │
222	┌──────────────┐   Channel<IrcMessage>   ┌┴───────────────────┐ │
223	│  Read Loop   │ ──────────────────────► │  Message           │ │
224	│  (network)   │   (inbound)             │  Processor         │ │
225	└──────────────┘                         │                    ├─┤
226	                                         │  - PING/PONG       │ │
227	                                         │  - CAP negotiation │ │  ┌──────────────────┐
228	                                         │  - State updates   ├─┼─►│  Plugin B Task   │
229	                                         │  - Event fan-out   │ │  │  Channel<Event>  │
230	                                         └┬───────────────────┘ │  └──────────────────┘
231	                                          │                     │
232	                                          └─►  ... more plugins
233	
234	         (plugins call IBot.SendAsync from any task)
235	                          │
236	                          ▼
237	┌──────────────┐   Channel<IrcMessage>   ┌──────────────────┐
238	│  Write Loop  │ ◄────────────────────── │  Rate Limiter    │
239	│  (network)   │   (outbound)            │  (token bucket)  │
240	└──────────────┘                         └──────────────────┘
241	```
242	
243	1. **Read Loop**: A dedicated async task reads from the TCP stream,
244	   parses raw lines into `IrcMessage` instances, and writes them to
245	   the inbound channel. This task does no processing beyond parsing.
246	
247	2. **Message Processor**: A dedicated async task reads from the
248	   inbound channel. For each message it:
249	   - Handles protocol-level concerns (PING/PONG, CAP negotiation)
250	   - Updates state tracking (channels, users, modes)
251	   - Translates raw `IrcMessage` into typed events
252	   - Writes the event to each plugin's individual event channel
253	
254	3. **Plugin Tasks**: Each plugin has its own dedicated async task and
255	   `Channel<MarvEvent>`. The task reads events from the channel and
256	   calls `plugin.HandleEventAsync(event, ct)` for each one — the
257	   core never calls handler methods directly. This means:
258	   - Each plugin processes events independently and concurrently with
259	     other plugins
260	   - Within a single plugin, `HandleEventAsync` is never called
261	     concurrently with itself — no concurrency within a plugin
262	   - A slow plugin does not block other plugins or state tracking
263	   - Event ordering is preserved within each plugin
264	
265	4. **Rate Limiter**: Accepts outbound messages from any task (plugins
266	   call `IBot.SendAsync` which writes to this component) and drains
267	   them to the outbound channel at a rate that respects the server's
268	   flood limits.
269	
270	5. **Write Loop**: A dedicated async task reads from the outbound
271	   channel and writes serialized messages to the TCP stream.
272	
273	### Concurrency Rules
274	
275	- **`HandleEventAsync` is called sequentially within each plugin task.**
276	  A plugin's event handler is never called concurrently with itself.
277	  But different plugins' handlers do run concurrently.
278	
279	- **State stores are read-safe from any plugin task.** The message
280	  processor updates state before fanning out events. State stores use
281	  concurrent-read-safe data structures, so plugins can safely query
282	  `IBot.Channels` and `IBot.Users` from their event handlers without
283	  synchronization.
284	
285	- **`IBot.SendAsync` (and its variants) is thread-safe.** It can be
286	  called from any plugin task, background tasks, timers, etc.
287	
288	- **`CancellationToken` propagation**: All async methods accept a
289	  `CancellationToken`. The bot's top-level token is cancelled on
290	  shutdown, which drains the channels and allows tasks to exit cleanly.
291	
292	### Labeled Response Correlation
293	
294	When the bot sends a command that expects a response (e.g., WHO,
295	WHOIS), it uses the `labeled-response` capability to tag the outbound
296	message with a unique label. The message processor collects responses
297	with matching labels and delivers them as a batch to the caller via a
298	`TaskCompletionSource<T>`. This allows:
299	
300	```
301	var whoReply = await bot.SendAndAwaitAsync(whoMessage, cancellationToken);
302	```
303	
304	`SendAndAwaitAsync` sends an IRC command and returns the server's
305	correlated response messages. It uses the `labeled-response` IRCv3
306	capability to tag the outbound message with a unique label, then
307	collects all inbound messages bearing that label until the server
308	signals completion. This is useful for commands like WHO, WHOIS, and
309	LIST where the response spans multiple messages.
310	
311	If `labeled-response` is not negotiated, the bot falls back to
312	sequential command queuing with timeout-based correlation.

316	## Plugin Discovery and Loading
317	
318	### Startup Sequence
319	
320	Plugin loading happens during application startup, before the IRC
321	connection is established. The app calls
322	`services.AddMarv(configuration)`, which triggers the following
323	sequence inside `Marv.Core`.
324	
325	#### Phase 1: Bootstrap (No DI)
326	
327	1. **Read plugin paths**: From the configuration (already parsed by
328	   the app), extract the list of plugin assembly paths.
329	
330	2. **Discover assemblies**: For each configured plugin path, load the
331	   assembly into an `AssemblyLoadContext`. Scan for types that
332	   implement `IPlugin` — each assembly must contain exactly one. Also
333	   scan for configuration classes tagged with `[PluginConfig]` and
334	   handler group classes tagged with `[HandlerGroup]`. Read each
335	   plugin's name for identification in logs, config, and diagnostics.
336	   The name is derived by stripping the "Plugin" suffix from the class
337	   name (e.g. `GreetPlugin` → `"Greet"`), or overridden with
338	   `[PluginName("CustomName")]`.
339	
340	3. **Build dependency graph**: Inspect each discovered plugin type:
341	   - Read `[ProvidesService]` attributes for service types the plugin
342	     provides
343	   - Read `[DependsOn]` attributes for explicit plugin ordering
344	   - Read constructor parameters to identify service dependencies
345	     (non-core types). Non-nullable parameters are required;
346	     nullable parameters with a default of `null` are optional.
347	   Construct a directed graph of plugin dependencies.
348	
349	4. **Topological sort**: Sort the graph. If there is a cycle, report
350	   it and fail startup. If a required dependency is missing, report
351	   it and fail startup. Optional dependencies participate in ordering
352	   (if present, the provider loads first) but do not block startup if
353	   absent.
354	
355	#### Phase 2: DI Container Build
356	
357	5. **Core service registration**: Register core services into the
358	   `IServiceCollection`: logging, configuration, `IIrcConnection`,
359	   `ICapabilityManager`, `IChannelStore`, `IUserStore`, `IBot`.
360	
361	6. **Plugin configuration registration**: For each configuration class
362	   tagged with `[PluginConfig(Section = "Name")]`, automatically
363	   register `IOptions<TConfig>` bound to the `Plugins:{Section}`
364	   configuration section. No boilerplate needed in the plugin —
365	   plugins access configuration via constructor injection of
366	   `IOptions<TConfig>`.
367	
368	7. **Plugin service registration**: For each plugin type (in
369	   dependency order), call its static `ConfigureServices` method
370	   (defined on `IPlugin` with an empty default implementation).
371	   Plugins that provide services to other plugins register their
372	   implementations here. Plugins that only handle events and use
373	   configuration do not need to override this method.
374	
375	8. **Build container**: Call `BuildServiceProvider()` to create the
376	   single `IServiceProvider`. Note that plugin types and handler
377	   group types are **not** registered in the container — they are
378	   created via `ActivatorUtilities` (through `IPluginActivator`).
379	
380	9. **Instantiate plugins**: Create each plugin instance via
381	   `ActivatorUtilities.CreateInstance`. Constructor parameters
382	   (configuration, services, `IBot`, `IPluginActivator`) are
383	   resolved from the container. Handler groups are created by
384	   `MarvPlugin` via `IPluginActivator` during construction.
385	
386	10. **Initialize plugins**: Call `OnLoadAsync()` on each plugin in
387	    dependency order. `MarvPlugin`'s default implementation forwards
388	    to handler group lifecycle methods.
389	
390	#### Runtime
391	
392	12. **Connect**: Establish the IRC connection, negotiate capabilities,
393	    authenticate, join channels.
394	
395	13. **Notify plugins**: Call `OnConnectedAsync()` on each plugin and
396	    its handler groups.
397	
398	14. **Start plugin tasks**: Create a dedicated `Channel<MarvEvent>`
399	    and async task for each plugin. The task reads events and calls
400	    `plugin.HandleEventAsync(event, ct)` — the core never calls
401	    handler methods directly.
402	
403	    For `MarvPlugin` subclasses, `HandleEventAsync` uses reflection
404	    to dispatch to attributed handler methods (`[OnEvent]`,
405	    `[OnCommand]`, `[OnRegex]`, `[OnRawMessage]`, `[OnInterval]`)
406	    on both the plugin class and its handler groups. The core does
407	    not interact with handler groups at all — `MarvPlugin` owns
408	    their creation (via `IPluginActivator`), lifecycle forwarding,
409	    and event dispatch. Handler methods on the plugin class do not
410	    need to be public (dispatch is from within the base class);
411	    handler methods on handler groups must be public. If multiple
412	    handlers match the same event, they are called consecutively in
413	    an undefined order.
414	
415	    Direct `IPlugin` implementations provide their own
416	    `HandleEventAsync` logic.
417	
418	15. **Message loop**: Process messages, update state, fan out events
419	    to plugin channels.
420	
421	16. **Reconnection**: On disconnection, all state is discarded:
422	    pending `SendAndAwaitAsync` calls are cancelled, outbound message
423	    queues are cleared, and channel/user state stores are reset.
424	    Plugins are notified via `OnDisconnectedAsync`, then
425	    `OnUnloadAsync`. Plugin and handler group instances are discarded.
426	    The bot reconnects with exponential backoff, then reinstantiates
427	    all plugins via `ActivatorUtilities` (step 9) and repeats from
428	    step 10. This ensures no stale references survive a reconnection.
429	
430	17. **Shutdown**: Signal all plugin tasks to stop. Call
431	    `OnDisconnectedAsync()` then `OnUnloadAsync()` on each plugin
432	    (and its handler groups) in reverse dependency order. Dispose the
433	    DI container.
434	
435	### Assembly Load Context
436	
437	Each plugin assembly is loaded into a shared `AssemblyLoadContext`.
438	Using a single shared context (rather than isolated contexts per
439	plugin) avoids type identity issues — interfaces defined in
440	`Marv.Core` or in a shared contracts assembly are the same `Type`
441	across all plugins.
442	
443	If we later need assembly isolation (e.g., for hot-reloading or
444	conflicting dependencies), we can revisit this, but the single-context
445	approach is simpler and avoids a class of subtle bugs.

449	## Inter-Plugin Services
450	
451	### How It Works
452	
453	**Providing a service**: A plugin declares `[ProvidesService]` on its
454	class and overrides the static `ConfigureServices` method from
455	`IPlugin`. The attribute tells the dependency sorter which plugin
456	provides which service type; the method does the actual DI
457	registration.
458	
459	**Consuming a service**: A plugin declares a constructor parameter of
460	the service type. The plugin loader inspects constructor parameters to
461	identify consumed services. Non-nullable parameters are required
462	dependencies; nullable parameters with a default of `null` are
463	optional.
464	
465	**Explicit ordering**: `[DependsOn(typeof(OtherPlugin))]` forces load
466	ordering without implying a service relationship.
467	
468	### Example
469	
470	```csharp
471	// Auth plugin provides IAuthorizationService
472	[ProvidesService(typeof(IAuthorizationService))]
473	public class AuthPlugin : MarvPlugin
474	{
475	    public AuthPlugin(IBot bot, IPluginActivator activator)
476	        : base(bot, activator) { }
477	
478	    public static void ConfigureServices(IServiceCollection services)
479	    {
480	        services.AddSingleton<IAuthorizationService, AccountBasedAuthService>();
481	    }
482	}
483	
484	// Moderation plugin consumes IAuthorizationService (required)
485	public class ModerationPlugin : MarvPlugin
486	{
487	    public ModerationPlugin(IBot bot, IPluginActivator activator,
488	        IAuthorizationService auth) : base(bot, activator) { ... }
489	}
490	
491	// Greet plugin consumes IAuthorizationService (optional)
492	public class GreetPlugin : MarvPlugin
493	{
494	    public GreetPlugin(
495	        IBot bot, IPluginActivator activator,
496	        IOptions<GreetPluginConfig> config,
497	        IAuthorizationService? auth = null) : base(bot, activator) { ... }
498	}
499	```
500	
501	The loader sees:
502	- `AuthPlugin` provides `IAuthorizationService` (from attribute)
503	- `ModerationPlugin` requires `IAuthorizationService` (from
504	  constructor, non-nullable)
505	- `GreetPlugin` optionally uses `IAuthorizationService` (from
506	  constructor, nullable with default `null`)
507	
508	Load order: AuthPlugin → ModerationPlugin, GreetPlugin (order between
509	Moderation and Greet is unspecified since neither depends on the
510	other).
511	
512	### Load Order Details
513	
514	The dependency sorter builds a graph from:
515	
516	- `[DependsOn(typeof(OtherPlugin))]` — direct plugin dependency
517	- Required constructor parameters — resolved to the plugin with a
518	  matching `[ProvidesService]` attribute
519	- Nullable constructor parameters with default `null` —
520	  ordered-if-present
521	
522	The graph is topologically sorted. Plugins with no dependencies load
523	first; plugins with dependencies load after their providers.
524	
525	**Cycle detection**: A cycle in the dependency graph is a
526	configuration error. The bot reports the cycle and refuses to start.
527	
528	**Missing required dependency**: If plugin A requires
529	`IAuthorizationService` but no loaded plugin provides it, startup
530	fails with a clear error message naming the missing service and the
531	plugin(s) that need it.
532	
533	**Missing optional dependency**: If plugin A optionally consumes
534	`IAuthorizationService` and no plugin provides it, A loads normally.
535	The constructor receives `null` for that parameter.
536	
537	### Diagnostics
538	
539	At startup (and available via a status command), the bot logs:
540	
541	- Which plugins are loaded, in what order
542	- Which services each plugin provides (from `[ProvidesService]`)
543	- Which services each plugin consumes (from constructors)
544	- Any plugins that were skipped and why

548	## Configuration
549	
550	Configuration is layered, with later sources overriding earlier ones:
551	
552	1. **Default values** (hardcoded in configuration classes)
553	2. **Configuration file** (`marv.json` by default). A `--config`
554	   CLI argument allows specifying an alternative path; the file
555	   extension determines the format (`.json` for JSON, `.yaml`/`.yml`
556	   for YAML, etc. via the appropriate
557	   `Microsoft.Extensions.Configuration` provider).
558	3. **Environment variables** (`MARV_*` prefix, double-underscore for
559	   nesting: `MARV_IRC__SERVER`)
560	4. **Command-line arguments** (`--irc:server=irc.example.com`)
561	
562	This uses the standard `Microsoft.Extensions.Configuration` stack.
563	Command-line parsing uses `System.CommandLine` 2.x.
564	
565	### Plugin Configuration
566	
567	Plugins that need configuration declare a configuration class tagged
568	with `[PluginConfig]`:
569	
570	```csharp
571	[PluginConfig(Section = "Greet")]
572	public record GreetPluginConfig
573	{
574	    public string GreetMessage { get; init; } = "Hello, {nick}!";
575	    public bool GreetOnJoin { get; init; } = true;
576	}
577	
578	public class GreetPlugin : MarvPlugin
579	{
580	    private readonly GreetPluginConfig _config;
581	
582	    public GreetPlugin(IBot bot, IPluginActivator activator,
583	        IOptions<GreetPluginConfig> config) : base(bot, activator)
584	    {
585	        _config = config.Value;
586	    }
587	}
588	```
589	
590	The plugin loader discovers configuration classes tagged with
591	`[PluginConfig(Section = "Name")]` during assembly scanning and
592	automatically registers `IOptions<TConfig>` bound to the
593	`Plugins:{Section}` configuration section. Plugins access their
594	configuration via constructor injection of `IOptions<TConfig>`.
595	
596	There is no need for a `ConfigureServices` method just for
597	configuration — this is handled automatically. Only plugins that
598	register services for other plugins to consume need
599	`ConfigureServices`.

603	## Error Handling
604	
605	- **Parse errors**: Malformed messages from the server are logged and
606	  skipped — they never crash the message processor.
607	- **Plugin handler exceptions**: Caught by the plugin's event loop
608	  task, logged with the plugin name and event type, and do not affect
609	  other plugins or the message loop.
610	- **Connection loss**: The connection layer signals disconnection. All
611	  pending `SendAndAwaitAsync` calls are cancelled, outbound message
612	  queues are cleared, and channel/user state stores are reset. The bot
613	  notifies plugins via `OnDisconnectedAsync`, then begins reconnection
614	  with exponential backoff.
615	- **Startup failures**: Missing required plugins/services, config
616	  validation errors, and dependency cycles all produce clear error
617	  messages and prevent the bot from starting.

133	### Concurrency Model
134

144	  never see a partial write.

146	  `user.Nick` and then `user.Host` in the same handler, a NICK or
147	  CHGHOST change could land between the two reads. In practice this
148	  is rare and usually harmless. Plugins that need strict consistency
149	  across multiple properties should copy the values they need into
150	  locals at the start of their handler.
151	- **Collection enumeration is safe.** Backing collections use
152	  `ConcurrentDictionary`, which safely handles concurrent reads and
153	  writes. Iterating `Channel.Members` while the message processor
154	  adds or removes a member will not throw.

157	case-mapped keys. The channel store is similarly structured. On

334	### Batched Messages
335	
336	When the server sends a `BATCH` group, individual messages within the
337	batch are delivered as normal typed events — each carries a `BatchId`
338	property linking it to the batch. Plugins that don't care about
339	batching simply ignore `BatchId` and process events normally.
340

342	netsplit QUITs atomically) can subscribe to the batch start/end

351	individual and batched event delivery. The default path (ignore
352	batching) works without any special handling.
353	
354	### Event Ordering
355	
356	Events are dispatched per-plugin (each plugin has its own channel and
357	task — see `architecture.md`). The ordering guarantees are:
358	
359	1. State tracking updates happen before events are fanned out
360	2. `RawMessageEvent` is dispatched before the corresponding typed
361	   event
362	3. Within a single plugin, events arrive in the order the server
363	   sent them
364	4. Across plugins, events are delivered concurrently — there is no
365	   ordering guarantee between different plugins' handling of the same
366	   event

using System.IO.Pipelines;
using System.Net.Security;
using System.Net.Sockets;
using System.Text;
using System.Threading.Channels;
using Marv.Core.Protocol;
using Microsoft.Extensions.Logging;

namespace Marv.Core.Irc;

/// <summary>
/// Manages the TCP/TLS connection to an IRC server. Provides inbound and outbound
/// channels for parsed IRC messages, with a rate limiter on outbound sends.
/// </summary>
internal sealed class IrcConnection : IAsyncDisposable
{
    private readonly ILogger _logger;
    private TcpClient? _tcpClient;
    private Stream? _stream;
    private CancellationTokenSource? _connectionCts;
    private Task? _readTask;
    private Task? _writeTask;

    private Channel<IrcMessage>? _inboundChannel;
    private Channel<IrcMessage>? _outboundChannel;

    // Rate limiter: token bucket — 5 messages burst, refill 1 per 2 seconds
    private const int BurstLimit = 5;
    private const double RefillRatePerSecond = 0.5;
    private double _tokens = BurstLimit;
    private DateTimeOffset _lastRefill = DateTimeOffset.UtcNow;
    private readonly object _rateLock = new();

    public IrcConnection(ILogger logger)
    {
        _logger = logger;
    }

    /// <summary>Reader for inbound parsed IRC messages from the server.</summary>
    public ChannelReader<IrcMessage> Inbound => _inboundChannel?.Reader
        ?? throw new InvalidOperationException("Not connected.");

    /// <summary>Writer for outbound IRC messages to the server.</summary>
    public ChannelWriter<IrcMessage> Outbound => _outboundChannel?.Writer
        ?? throw new InvalidOperationException("Not connected.");

    /// <summary>True if the connection is currently established.</summary>
    public bool IsConnected => _tcpClient?.Connected == true;

    /// <summary>
    /// Establishes a TCP (optionally TLS) connection to the IRC server and starts
    /// the read/write loop tasks.
    /// </summary>
    public async Task ConnectAsync(string host, int port, bool useTls, CancellationToken ct)
    {
        _tcpClient = new TcpClient();
        await _tcpClient.ConnectAsync(host, port, ct);

        Stream stream = _tcpClient.GetStream();

        if (useTls)
        {
            var sslStream = new SslStream(stream, leaveInnerStreamOpen: false);
            await sslStream.AuthenticateAsClientAsync(host);
            stream = sslStream;
        }

        _stream = stream;
        _connectionCts = CancellationTokenSource.CreateLinkedTokenSource(ct);

        _inboundChannel = Channel.CreateUnbounded<IrcMessage>(new UnboundedChannelOptions
        {
            SingleReader = true,
            SingleWriter = true
        });

        _outboundChannel = Channel.CreateBounded<IrcMessage>(new BoundedChannelOptions(512)
        {
            SingleReader = true,
            SingleWriter = false,
            FullMode = BoundedChannelFullMode.Wait
        });

        _tokens = BurstLimit;
        _lastRefill = DateTimeOffset.UtcNow;

        var loopCt = _connectionCts.Token;
        _readTask = Task.Run(() => ReadLoopAsync(loopCt), loopCt);
        _writeTask = Task.Run(() => WriteLoopAsync(loopCt), loopCt);

        _logger.LogInformation("Connected to {Host}:{Port} (TLS: {UseTls})", host, port, useTls);
    }

    /// <summary>
    /// Closes the connection and stops the read/write loops.
    /// </summary>
    public async Task DisconnectAsync()
    {
        if (_connectionCts is not null)
        {
            await _connectionCts.CancelAsync();
        }

        _outboundChannel?.Writer.TryComplete();
        _inboundChannel?.Writer.TryComplete();

        if (_readTask is not null)
        {
            try { await _readTask; } catch (OperationCanceledException) { }
        }

        if (_writeTask is not null)
        {
            try { await _writeTask; } catch (OperationCanceledException) { }
        }

        if (_stream is not null)
        {
            await _stream.DisposeAsync();
            _stream = null;
        }

        _tcpClient?.Dispose();
        _tcpClient = null;

        _connectionCts?.Dispose();
        _connectionCts = null;

        _logger.LogInformation("Disconnected");
    }

    /// <summary>
    /// Reads lines from the TCP stream, parses them into IrcMessage, and writes
    /// to the inbound channel. Runs until cancelled or the stream closes.
    /// </summary>
    private async Task ReadLoopAsync(CancellationToken ct)
    {
        var writer = _inboundChannel!.Writer;

        try
        {
            using var reader = new StreamReader(_stream!, Encoding.UTF8, detectEncodingFromByteOrderMarks: false,
                bufferSize: 4096, leaveOpen: true);

            while (!ct.IsCancellationRequested)
            {
                var line = await reader.ReadLineAsync(ct);
                if (line is null)
                {
                    _logger.LogInformation("Server closed the connection");
                    break;
                }

                if (string.IsNullOrWhiteSpace(line))
                    continue;

                _logger.LogTrace("<< {Line}", line);

                var message = IrcParser.Parse(line);
                if (message is not null)
                {
                    await writer.WriteAsync(message, ct);
                }
                else
                {
                    _logger.LogWarning("Failed to parse IRC message: {Line}", line);
                }
            }
        }
        catch (OperationCanceledException) when (ct.IsCancellationRequested)
        {
            // Normal shutdown
        }
        catch (IOException ex)
        {
            _logger.LogWarning(ex, "Read loop terminated due to I/O error");
        }
        catch (Exception ex)
        {
            _logger.LogError(ex, "Read loop terminated unexpectedly");
        }
        finally
        {
            writer.TryComplete();
        }
    }

    /// <summary>
    /// Reads from the outbound channel, applies rate limiting, serializes, and
    /// writes to the TCP stream. Runs until cancelled or the channel completes.
    /// </summary>
    private async Task WriteLoopAsync(CancellationToken ct)
    {
        var reader = _outboundChannel!.Reader;

        try
        {
            await foreach (var message in reader.ReadAllAsync(ct))
            {
                await WaitForTokenAsync(ct);

                var line = IrcSerializer.Serialize(message);
                _logger.LogTrace(">> {Line}", line);

                var bytes = Encoding.UTF8.GetBytes(line + "\r\n");
                await _stream!.WriteAsync(bytes, ct);
                await _stream.FlushAsync(ct);
            }
        }
        catch (OperationCanceledException) when (ct.IsCancellationRequested)
        {
            // Normal shutdown
        }
        catch (IOException ex)
        {
            _logger.LogWarning(ex, "Write loop terminated due to I/O error");
        }
        catch (Exception ex)
        {
            _logger.LogError(ex, "Write loop terminated unexpectedly");
        }
    }

    /// <summary>
    /// Token bucket rate limiter. Waits until a token is available before allowing a send.
    /// </summary>
    private async Task WaitForTokenAsync(CancellationToken ct)
    {
        while (true)
        {
            ct.ThrowIfCancellationRequested();

            lock (_rateLock)
            {
                var now = DateTimeOffset.UtcNow;
                var elapsed = (now - _lastRefill).TotalSeconds;
                _tokens = Math.Min(BurstLimit, _tokens + elapsed * RefillRatePerSecond);
                _lastRefill = now;

                if (_tokens >= 1.0)
                {
                    _tokens -= 1.0;
                    return;
                }
            }

            await Task.Delay(100, ct);
        }
    }

    public async ValueTask DisposeAsync()
    {
        await DisconnectAsync();
    }
}

    {
        if (key is not null)
            await SendRawAsync(new IrcMessage("JOIN", [channel, key]), ct);
        else
            await SendRawAsync(new IrcMessage("JOIN", [channel]), ct);
    }

    public async Task PartAsync(string channel, string? reason, CancellationToken ct)
    {
        if (reason is not null)
            await SendRawAsync(new IrcMessage("PART", [channel, reason]), ct);

            await SendRawAsync(new IrcMessage("PART", [channel]), ct);
    }

    /// <inheritdoc />
    public async Task<IReadOnlyList<IrcMessage>> SendAndAwaitAsync(IrcMessage message, CancellationToken ct)
    {
        if (_capabilityManager.IsNegotiated(Platform.Capabilities.LabeledResponse))
        {
            var label = $"marv-{Interlocked.Increment(ref _labelCounter)}";
            var tags = new Dictionary<string, string?>(message.Tags) { ["label"] = label };
            var labeled = new IrcMessage(tags.AsReadOnly(), message.Source, message.Command, message.Parameters);

            var tcs = new TaskCompletionSource<IReadOnlyList<IrcMessage>>(TaskCreationOptions.RunContinuationsAsynchronously);
            _pendingLabels[label] = tcs;
            _labelBuffers[label] = [];

            await SendRawAsync(labeled, ct);

            using var timeoutCts = CancellationTokenSource.CreateLinkedTokenSource(ct);
            timeoutCts.CancelAfter(TimeSpan.FromSeconds(30));

            try
            {
                return await tcs.Task.WaitAsync(timeoutCts.Token);
            }
            catch (OperationCanceledException) when (!ct.IsCancellationRequested)
            {
                _pendingLabels.TryRemove(label, out _);
                _labelBuffers.TryRemove(label, out _);
                throw new TimeoutException($"Timed out waiting for labeled response '{label}'.");
            }
        }
        else
        {
            // Fallback: just send and return empty (no correlation available)
            await SendRawAsync(message, ct);
            return [];
        }
    }

    /// <summary>
    /// Connects to the IRC server, performs registration (CAP, NICK, USER),
    /// and runs the message processor until disconnected or cancelled.
    /// </summary>
    public async Task RunAsync(IrcConnection connection, IrcConfiguration config,
        IReadOnlyList<ChannelWriter<MarvEvent>> eventWriters, CancellationToken ct)
    {
        _connection = connection;
        _config = config;
        _eventWriters = eventWriters;
        _currentNick = config.Nick;
        _capNegotiationDone = false;
        _saslInProgress = false;
        _pendingCaps.Clear();

        var comparer = CaseMapping.GetComparer(_serverInfo.CaseMapping);
        _self = new IrcUser(_currentNick, comparer);
        _users.Clear();
        _channels.Clear();

        _registrationTcs = new TaskCompletionSource<bool>(TaskCreationOptions.RunContinuationsAsynchronously);

        // Begin CAP negotiation and registration
        await SendRawAsync(new IrcMessage("CAP", ["LS", "302"]), ct);
        await SendRawAsync(new IrcMessage("NICK", [config.Nick]), ct);
        await SendRawAsync(new IrcMessage("USER", [config.User, "0", "*", config.RealName]), ct);

        // Process messages
        await ProcessMessagesAsync(ct);
    }

    /// <summary>
    /// Resets state on disconnection — clears users, channels, pending labels.
    /// </summary>
    public void ResetState()
    {
        _users.Clear();
        _channels.Clear();
        _serverInfo.Reset();
        _capabilityManager.Reset();

        foreach (var kvp in _pendingLabels)
        {
            kvp.Value.TrySetCanceled();
        }
        _pendingLabels.Clear();
        _labelBuffers.Clear();

        _eventWriters = [];
        _connection = null;
    }

    // --- Message processor ---

    private async Task ProcessMessagesAsync(CancellationToken ct)
    {
        try
        {
            await foreach (var message in _connection!.Inbound.ReadAllAsync(ct))
            {
                try
                {
                    await ProcessMessageAsync(message, ct);
                }
                catch (OperationCanceledException) when (ct.IsCancellationRequested)
                {
                    break;
                }
                catch (Exception ex)
                {
                    _logger.LogError(ex, "Error processing message: {Command}", message.Command);
                }
            }
        }
        catch (OperationCanceledException) when (ct.IsCancellationRequested)
        {
            // Normal shutdown
        }
    }

    private async Task ProcessMessageAsync(IrcMessage message, CancellationToken ct)
    {
        // Check for labeled-response correlation
        if (message.Tags.TryGetValue("label", out var label) && label is not null
            && _labelBuffers.TryGetValue(label, out var buffer))
        {
            buffer.Add(message);

            // ACK with label means the response is complete
            if (message.Command == "ACK" && _pendingLabels.TryRemove(label, out var tcs))
            {
                _labelBuffers.TryRemove(label, out _);
                tcs.TrySetResult(buffer);
                return;
            }
        }

        // Dispatch RawMessageEvent before typed events
        var rawEvent = CreateEvent<RawMessageEvent>(message);
        await FanOutEventAsync(rawEvent, ct);

        switch (message.Command)
        {
            case "PING":
                await HandlePing(message, ct);
                break;

            case "PONG":
                break; // Ignore server PONGs

            case "CAP":
                await HandleCap(message, ct);
                break;

            case "AUTHENTICATE":
                await HandleAuthenticate(message, ct);
                break;

            // Registration numerics
            case "001": // RPL_WELCOME
                await HandleWelcome(message, ct);
                break;
            case "005": // RPL_ISUPPORT
                HandleISupport(message);
                break;
            case "376": // RPL_ENDOFMOTD
            case "422": // ERR_NOMOTD
                await HandleEndOfMotd(message, ct);
                break;

            // SASL numerics
            case "900": // RPL_LOGGEDIN
                HandleSaslSuccess(message);
                break;
            case "903": // RPL_SASLSUCCESS
                await HandleSaslComplete(message, ct);
                break;
            case "902": // ERR_NICKLOCKED
            case "904": // ERR_SASLFAIL
            case "905": // ERR_SASLTOOLONG
            case "906": // ERR_SASLABORTED
            case "907": // ERR_SASLALREADY
                await HandleSaslFailed(message, ct);
                break;

            // Channel/user state
            case "PRIVMSG":
                await HandlePrivmsg(message, ct);
                break;
            case "NOTICE":
                await HandleNotice(message, ct);
                break;
            case "JOIN":
                await HandleJoin(message, ct);
                break;
            case "PART":
                await HandlePart(message, ct);
                break;
            case "KICK":
                await HandleKick(message, ct);
                break;
            case "QUIT":
                await HandleQuit(message, ct);
                break;
            case "NICK":
                await HandleNick(message, ct);
                break;
            case "MODE":
                await HandleMode(message, ct);
                break;
            case "TOPIC":
                await HandleTopic(message, ct);
                break;
            case "INVITE":
                await HandleInvite(message, ct);
                break;
            case "ACCOUNT":
                await HandleAccount(message, ct);
                break;
            case "AWAY":
                await HandleAway(message, ct);
                break;
            case "CHGHOST":
                await HandleChghost(message, ct);
                break;
            case "BATCH":
                await HandleBatch(message, ct);
                break;

            // NAMES replies
            case "353": // RPL_NAMREPLY
                HandleNamesReply(message);
                break;
            case "366": // RPL_ENDOFNAMES
                break;

            // TOPIC replies
            case "332": // RPL_TOPIC
                HandleTopicReply(message);
                break;
            case "333": // RPL_TOPICWHOTIME
                HandleTopicWhoTime(message);
                break;

            // Channel creation time
            case "329": // RPL_CREATIONTIME
                HandleCreationTime(message);
                break;

            // Nick errors
            case "431": // ERR_NONICKNAMEGIVEN
            case "432": // ERR_ERRONEUSNICKNAME
            case "433": // ERR_NICKNAMEINUSE
            case "436": // ERR_NICKCOLLISION
                await HandleNickError(message, ct);
                break;

            default:
                _logger.LogDebug("Unhandled command: {Command}", message.Command);
                break;
        }
    }

    // --- Protocol handlers ---

    private async Task HandlePing(IrcMessage message, CancellationToken ct)
    {
        var param = message.Parameters.Count > 0 ? message.Parameters[0] : "";
        await SendRawAsync(new IrcMessage("PONG", [param]), ct);
    }

    private async Task HandleCap(IrcMessage message, CancellationToken ct)
    {
        if (message.Parameters.Count < 3) return;

        var subCommand = message.Parameters[1].ToUpperInvariant();
        var isMultiLine = message.Parameters.Count > 3 && message.Parameters[2] == "*";
        var capList = message.Parameters[isMultiLine ? 3 : 2];

        switch (subCommand)
        {
            case "LS":
                foreach (var cap in ParseCapList(capList))
                {
                    _capabilityManager.SetAvailable(cap.Key, cap.Value);
                }

                if (!isMultiLine)
                {
                    // All capabilities listed — request the ones we want
                    var toRequest = DesiredCapabilities
                        .Where(c => _capabilityManager.IsAvailable(c))
                        .ToList();

                    if (toRequest.Count > 0)
                    {
                        _logger.LogInformation("Requesting capabilities: {Caps}",
                            string.Join(", ", toRequest));
                        await SendRawAsync(new IrcMessage("CAP", ["REQ", string.Join(' ', toRequest)]), ct);
                    }
                    else
                    {
                        await SendRawAsync(new IrcMessage("CAP", ["END"]), ct);
                        _capNegotiationDone = true;
                    }
                }
                break;

            case "ACK":
                foreach (var capName in capList.Split(' ', StringSplitOptions.RemoveEmptyEntries))
                {
                    _capabilityManager.SetNegotiated(capName);
                    _logger.LogDebug("Capability acknowledged: {Cap}", capName);
                }

                // Start SASL if negotiated and credentials are configured
                if (_capabilityManager.IsNegotiated(Platform.Capabilities.Sasl)
                    && _config.SaslUser is not null && _config.SaslPassword is not null
                    && !_saslInProgress)
                {
                    _saslInProgress = true;
                    await SendRawAsync(new IrcMessage("AUTHENTICATE", ["PLAIN"]), ct);
                }
                else
                {
                    await SendRawAsync(new IrcMessage("CAP", ["END"]), ct);
                    _capNegotiationDone = true;
                }
                break;

            case "NAK":
                _logger.LogWarning("Capabilities rejected: {Caps}", capList);
                await SendRawAsync(new IrcMessage("CAP", ["END"]), ct);
                _capNegotiationDone = true;
                break;

            case "NEW":
                foreach (var cap in ParseCapList(capList))
                {
                    _capabilityManager.AddNewCapability(cap.Key, cap.Value);
                }
                var newCaps = ParseCapList(capList)
                    .Where(c => DesiredCapabilities.Contains(c.Key, StringComparer.OrdinalIgnoreCase))
                    .Select(c => c.Key)
                    .ToList();
                if (newCaps.Count > 0)
                {
                    await SendRawAsync(new IrcMessage("CAP", ["REQ", string.Join(' ', newCaps)]), ct);
                }

                var capChangedNew = CreateEvent<CapabilitiesChangedEvent>(message);
                await FanOutEventAsync(capChangedNew, ct);
                break;

            case "DEL":
                foreach (var capName in capList.Split(' ', StringSplitOptions.RemoveEmptyEntries))
                {
                    _capabilityManager.RemoveCapability(capName);
                    _logger.LogDebug("Capability removed: {Cap}", capName);
                }

                var capChangedDel = CreateEvent<CapabilitiesChangedEvent>(message);
                await FanOutEventAsync(capChangedDel, ct);
                break;
        }
    }

    private async Task HandleAuthenticate(IrcMessage message, CancellationToken ct)
    {
        if (message.Parameters.Count > 0 && message.Parameters[0] == "+")
        {
            // Server is ready for SASL PLAIN credentials
            var authString = $"{_config.SaslUser}\0{_config.SaslUser}\0{_config.SaslPassword}";
            var encoded = Convert.ToBase64String(Encoding.UTF8.GetBytes(authString));
            await SendRawAsync(new IrcMessage("AUTHENTICATE", [encoded]), ct);
        }
    }

    private void HandleSaslSuccess(IrcMessage message)
    {
        if (message.Parameters.Count > 1)
        {
            _logger.LogInformation("SASL authentication successful: {Account}", message.Parameters[1]);
        }
    }

    private async Task HandleSaslComplete(IrcMessage message, CancellationToken ct)
    {
        _saslInProgress = false;
        _logger.LogInformation("SASL authentication complete");
        await SendRawAsync(new IrcMessage("CAP", ["END"]), ct);
        _capNegotiationDone = true;
    }

    private async Task HandleSaslFailed(IrcMessage message, CancellationToken ct)
    {
        _saslInProgress = false;
        _logger.LogWarning("SASL authentication failed: {Numeric} {Message}",
            message.Command, message.Parameters.LastOrDefault() ?? "");
        await SendRawAsync(new IrcMessage("CAP", ["END"]), ct);
        _capNegotiationDone = true;
    }

    private async Task HandleWelcome(IrcMessage message, CancellationToken ct)
    {
        // 001 gives us our actual nick in params[0]
        if (message.Parameters.Count > 0)
        {
            _currentNick = message.Parameters[0];
            _self.Nick = _currentNick;
        }

        _logger.LogInformation("Registered as {Nick}", _currentNick);
        _registrationTcs?.TrySetResult(true);

        var evt = CreateEvent<ConnectedEvent>(message);
        await FanOutEventAsync(evt, ct);
    }

    private void HandleISupport(IrcMessage message)
    {
        // 005 params: <nick> <token1> <token2> ... :are supported by this server
        for (var i = 1; i < message.Parameters.Count - 1; i++)
        {
            var token = message.Parameters[i];
            var eqIndex = token.IndexOf('=');
            if (eqIndex >= 0)
            {
                _serverInfo.SetToken(token[..eqIndex], token[(eqIndex + 1)..]);
            }
            else
            {
                _serverInfo.SetToken(token, null);
            }
        }
    }

    private async Task HandleEndOfMotd(IrcMessage message, CancellationToken ct)
    {
        // NickServ authentication if configured and SASL wasn't used
        if (_config.NickServPassword is not null && !_capabilityManager.IsNegotiated(Platform.Capabilities.Sasl))
        {
            _logger.LogInformation("Authenticating to NickServ");
            await SendMessageAsync("NickServ", $"IDENTIFY {_config.NickServPassword}", ct);
        }

        // Join configured channels
        foreach (var channel in _config.Channels)
        {
            _logger.LogInformation("Joining channel: {Channel}", channel);
            await JoinAsync(channel, null, ct);
        }
    }

    private async Task HandlePrivmsg(IrcMessage message, CancellationToken ct)
    {
        if (message.Parameters.Count < 2 || message.Source?.Nick is null) return;

        var target = message.Parameters[0];
        var text = message.Parameters[1];
        var sender = GetOrCreateUser(message.Source);

        // Check for CTCP
        if (text.StartsWith('\x01') && text.EndsWith('\x01'))
        {
            var ctcpContent = text[1..^1];
            await HandleCtcp(message, sender, target, ctcpContent, ct);
            return;
        }

        var isChannel = IsChannelName(target);
        IrcChannel? channel = isChannel ? GetChannel(target) : null;

        var evt = new MessageEvent
        {
            Timestamp = GetTimestamp(message),
            RawMessage = message,
            MessageId = message.Tags.GetValueOrDefault("msgid"),
            BatchId = message.Tags.GetValueOrDefault("batch"),
            Channel = channel,
            Sender = sender,
            Text = text,
            ReplyTo = message.Tags.GetValueOrDefault("+reply")
        };

        await FanOutEventAsync(evt, ct);
    }

    private async Task HandleCtcp(IrcMessage message, IrcUser sender, string target, string ctcpContent, CancellationToken ct)
    {
        var spaceIdx = ctcpContent.IndexOf(' ');
        var command = spaceIdx >= 0 ? ctcpContent[..spaceIdx].ToUpperInvariant() : ctcpContent.ToUpperInvariant();
        var args = spaceIdx >= 0 ? ctcpContent[(spaceIdx + 1)..] : null;

        switch (command)
        {
            case "ACTION":
            {
                var isChannel = IsChannelName(target);
                var channel = isChannel ? GetChannel(target) : null;
                var evt = new ActionEvent
                {
                    Timestamp = GetTimestamp(message),
                    RawMessage = message,
                    MessageId = message.Tags.GetValueOrDefault("msgid"),
                    BatchId = message.Tags.GetValueOrDefault("batch"),
                    Channel = channel,
                    Sender = sender,
                    Text = args ?? ""
                };
                await FanOutEventAsync(evt, ct);
                break;
            }
            case "VERSION":
                await SendRawAsync(new IrcMessage("NOTICE", [sender.Nick,
                    "\x01VERSION Marv IRC Bot 0.1.0\x01"]), ct);
                break;
            case "PING":
                await SendRawAsync(new IrcMessage("NOTICE", [sender.Nick,
                    $"\x01PING {args ?? ""}\x01"]), ct);
                break;
            case "TIME":
                await SendRawAsync(new IrcMessage("NOTICE", [sender.Nick,
                    $"\x01TIME {DateTimeOffset.UtcNow:R}\x01"]), ct);
                break;
            default:
            {
                var evt = new CtcpEvent
                {
                    Timestamp = GetTimestamp(message),
                    RawMessage = message,
                    MessageId = message.Tags.GetValueOrDefault("msgid"),
                    BatchId = message.Tags.GetValueOrDefault("batch"),
                    Sender = sender,
                    Command = command,
                    Args = args,
                    IsDirect = !IsChannelName(target)
                };
                await FanOutEventAsync(evt, ct);
                break;
            }
        }
    }

    private async Task HandleNotice(IrcMessage message, CancellationToken ct)
    {
        if (message.Parameters.Count < 2) return;

        // During registration, notices may come from the server (no nick)
        if (message.Source?.Nick is null) return;

        var target = message.Parameters[0];
        var text = message.Parameters[1];
        var sender = GetOrCreateUser(message.Source);
        var isChannel = IsChannelName(target);
        var channel = isChannel ? GetChannel(target) : null;

        var evt = new NoticeEvent
        {
            Timestamp = GetTimestamp(message),
            RawMessage = message,
            MessageId = message.Tags.GetValueOrDefault("msgid"),
            BatchId = message.Tags.GetValueOrDefault("batch"),
            Channel = channel,
            Sender = sender,
            Text = text
        };

        await FanOutEventAsync(evt, ct);
    }

    private async Task HandleJoin(IrcMessage message, CancellationToken ct)
    {
        if (message.Source?.Nick is null || message.Parameters.Count < 1) return;

        var channelName = message.Parameters[0];
        var user = GetOrCreateUser(message.Source);

        // extended-join: JOIN #channel account :realname
        string? account = null;
        if (_capabilityManager.IsNegotiated(Platform.Capabilities.ExtendedJoin) && message.Parameters.Count >= 2)
        {
            account = message.Parameters[1] == "*" ? null : message.Parameters[1];
            if (account is not null) user.Account = account;
            if (message.Parameters.Count >= 3)
                user.RealName = message.Parameters[2];
        }

        // Account from account-tag
        if (message.Tags.TryGetValue("account", out var acctTag) && acctTag is not null)
        {
            account = acctTag == "*" ? null : acctTag;
            if (account is not null) user.Account = account;
        }

        var comparer = CaseMapping.GetComparer(_serverInfo.CaseMapping);

        if (comparer.Equals(user.Nick, _currentNick))
        {
            // Bot is joining a channel
            var channel = new IrcChannel(channelName, comparer);
            channel.AddMember(user);
            _channels[channelName] = channel;
            _self = user;

            var evt = new UserJoinedEvent
            {
                Timestamp = GetTimestamp(message),
                RawMessage = message,
                MessageId = message.Tags.GetValueOrDefault("msgid"),
                BatchId = message.Tags.GetValueOrDefault("batch"),
                Channel = channel,
                User = user,
                Account = account
            };
            await FanOutEventAsync(evt, ct);
        }
        else
        {
            var channel = GetChannel(channelName);
            if (channel is not null)
            {
                channel.AddMember(user);
                user.AddChannel(channel);

                var evt = new UserJoinedEvent
                {
                    Timestamp = GetTimestamp(message),
                    RawMessage = message,
                    MessageId = message.Tags.GetValueOrDefault("msgid"),
                    BatchId = message.Tags.GetValueOrDefault("batch"),
                    Channel = channel,
                    User = user,
                    Account = account
                };
                await FanOutEventAsync(evt, ct);
            }
        }
    }

    private async Task HandlePart(IrcMessage message, CancellationToken ct)
    {
        if (message.Source?.Nick is null || message.Parameters.Count < 1) return;

        var channelName = message.Parameters[0];
        var reason = message.Parameters.Count > 1 ? message.Parameters[1] : null;
        var user = GetOrCreateUser(message.Source);
        var channel = GetChannel(channelName);
        if (channel is null) return;

        var comparer = CaseMapping.GetComparer(_serverInfo.CaseMapping);

        var evt = new UserPartedEvent
        {
            Timestamp = GetTimestamp(message),
            RawMessage = message,
            MessageId = message.Tags.GetValueOrDefault("msgid"),
            BatchId = message.Tags.GetValueOrDefault("batch"),
            Channel = channel,
            User = user,
            Reason = reason
        };
        await FanOutEventAsync(evt, ct);

        if (comparer.Equals(user.Nick, _currentNick))
        {
            // Bot left the channel
            _channels.TryRemove(channelName, out _);
        }
        else
        {
            channel.RemoveMember(user.Nick);
            user.RemoveChannel(channelName);
            MaybeForgetUser(user);
        }
    }

    private async Task HandleKick(IrcMessage message, CancellationToken ct)
    {
        if (message.Parameters.Count < 2 || message.Source?.Nick is null) return;

        var channelName = message.Parameters[0];
        var kickedNick = message.Parameters[1];
        var reason = message.Parameters.Count > 2 ? message.Parameters[2] : null;
        var channel = GetChannel(channelName);
        if (channel is null) return;

        var kicker = GetOrCreateUser(message.Source);
        var kicked = GetOrCreateUserByNick(kickedNick);

        var comparer = CaseMapping.GetComparer(_serverInfo.CaseMapping);

        var evt = new UserKickedEvent
        {
            Timestamp = GetTimestamp(message),
            RawMessage = message,
            MessageId = message.Tags.GetValueOrDefault("msgid"),
            BatchId = message.Tags.GetValueOrDefault("batch"),
            Channel = channel,
            Kicker = kicker,
            Kicked = kicked,
            Reason = reason
        };
        await FanOutEventAsync(evt, ct);

        if (comparer.Equals(kickedNick, _currentNick))
        {
            _channels.TryRemove(channelName, out _);
        }
        else
        {
            channel.RemoveMember(kickedNick);
            kicked.RemoveChannel(channelName);
            MaybeForgetUser(kicked);
        }
    }

    private async Task HandleQuit(IrcMessage message, CancellationToken ct)
    {
        if (message.Source?.Nick is null) return;

        var reason = message.Parameters.Count > 0 ? message.Parameters[0] : null;
        var user = GetOrCreateUser(message.Source);

        var affectedChannels = _channels.Values
            .Where(c => c.HasMember(user.Nick))
            .Cast<IChannel>()
            .ToList();

        var evt = new UserQuitEvent
        {
            Timestamp = GetTimestamp(message),
            RawMessage = message,
            MessageId = message.Tags.GetValueOrDefault("msgid"),
            BatchId = message.Tags.GetValueOrDefault("batch"),
            User = user,
            Reason = reason,
            AffectedChannels = affectedChannels
        };
        await FanOutEventAsync(evt, ct);

        // Remove user from all channels
        foreach (var channel in _channels.Values)
        {
            channel.RemoveMember(user.Nick);
        }
        _users.TryRemove(user.Nick, out _);
    }

    private async Task HandleNick(IrcMessage message, CancellationToken ct)
    {
        if (message.Source?.Nick is null || message.Parameters.Count < 1) return;

        var oldNick = message.Source.Nick;
        var newNick = message.Parameters[0];

        var comparer = CaseMapping.GetComparer(_serverInfo.CaseMapping);

        if (comparer.Equals(oldNick, _currentNick))
        {
            _currentNick = newNick;
        }

        if (_users.TryRemove(oldNick, out var user))
        {
            user.Nick = newNick;
            _users[newNick] = user;

            foreach (var channel in _channels.Values)
            {
                if (channel.HasMember(oldNick))
                {
                    channel.RenameMember(oldNick, newNick, user);
                }
            }

            var evt = new NickChangedEvent
            {
                Timestamp = GetTimestamp(message),
                RawMessage = message,
                MessageId = message.Tags.GetValueOrDefault("msgid"),
                BatchId = message.Tags.GetValueOrDefault("batch"),
                User = user,
                OldNick = oldNick,
                NewNick = newNick
            };
            await FanOutEventAsync(evt, ct);
        }
    }

    private async Task HandleMode(IrcMessage message, CancellationToken ct)
    {
        if (message.Parameters.Count < 2) return;

        var target = message.Parameters[0];
        if (!IsChannelName(target)) return; // User mode, ignore for now

        var channel = GetChannel(target);
        if (channel is null || message.Source?.Nick is null) return;

        var setter = GetOrCreateUser(message.Source);
        var modeString = message.Parameters[1];
        var changes = ParseModeChanges(modeString, message.Parameters, 2, channel);

        foreach (var change in changes)
        {
            ApplyModeChange(channel, change);
        }

        var evt = new ModeChangedEvent
        {
            Timestamp = GetTimestamp(message),
            RawMessage = message,
            MessageId = message.Tags.GetValueOrDefault("msgid"),
            BatchId = message.Tags.GetValueOrDefault("batch"),
            Channel = channel,
            SetBy = setter,
            Changes = changes
        };
        await FanOutEventAsync(evt, ct);
    }

    private async Task HandleTopic(IrcMessage message, CancellationToken ct)

                    ident = rest[(bangIdx + 1)..atIdx];
                    host = rest[(atIdx + 1)..];

                }

    private List<ModeChange> ParseModeChanges(string modeString, IReadOnlyList<string> parameters, int paramStart, IrcChannel channel)
    {
        var changes = new List<ModeChange>();
        var adding = true;
        var paramIdx = paramStart;

        foreach (var c in modeString)
        {
            if (c == '+') { adding = true; continue; }
            if (c == '-') { adding = false; continue; }

            string? param = null;
            var modeType = GetModeType(c);

            // Type A: always has parameter
            // Type B: always has parameter
            // Type C: has parameter when setting, not when unsetting
            // Type D: never has parameter
            // Prefix modes: always have parameter (the nick)
            if (_serverInfo.Prefix.HasMode(c))
            {
                if (paramIdx < parameters.Count)
                    param = parameters[paramIdx++];
            }
            else if (modeType is 'A' or 'B')
            {
                if (paramIdx < parameters.Count)
                    param = parameters[paramIdx++];
            }
            else if (modeType == 'C' && adding)
            {
                if (paramIdx < parameters.Count)
                    param = parameters[paramIdx++];
            }

            changes.Add(new ModeChange { IsSet = adding, Mode = c, Parameter = param });
        }

        return changes;
    }

    {

        if (chanModes.TypeB.Contains(mode)) return 'B';
        if (chanModes.TypeC.Contains(mode)) return 'C';
        if (chanModes.TypeD.Contains(mode)) return 'D';
        return 'D'; // Default to no-parameter
    }

    private void ApplyModeChange(IrcChannel channel, ModeChange change)
    {
        // Prefix modes affect user status in channel
        if (_serverInfo.Prefix.HasMode(change.Mode) && change.Parameter is not null)

            channel.SetMode(change.Mode, change.Parameter);
        else
            channel.UnsetMode(change.Mode);
    }

/// <summary>
/// Hosted service that orchestrates the bot's lifecycle: plugin loading,
/// IRC connection, message processing, reconnection, and graceful shutdown.
/// </summary>
internal sealed class MarvBotService : BackgroundService
{
    private readonly ILogger<MarvBotService> _logger;
    private readonly IrcBot _bot;
    private readonly PluginManager _pluginManager;
    private readonly IReadOnlyList<PluginDescriptor> _descriptors;
    private readonly IrcConfiguration _config;
    private readonly ILoggerFactory _loggerFactory;

    // Reconnection backoff
    private const int InitialBackoffSeconds = 5;
    private const int MaxBackoffSeconds = 300;

    public MarvBotService(
        ILogger<MarvBotService> logger,
        IrcBot bot,
        PluginManager pluginManager,
        IReadOnlyList<PluginDescriptor> descriptors,
        IOptions<IrcConfiguration> config,
        ILoggerFactory loggerFactory)
    {
        _logger = logger;
        _bot = bot;
        _pluginManager = pluginManager;
        _descriptors = descriptors;
        _config = config.Value;
        _loggerFactory = loggerFactory;
    }

    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        var backoff = InitialBackoffSeconds;

        while (!stoppingToken.IsCancellationRequested)
        {
            try
            {
                // Phase 1: Instantiate and load plugins
                _pluginManager.InstantiatePlugins(_descriptors);
                await _pluginManager.LoadPluginsAsync(stoppingToken);
                _pluginManager.LogDiagnostics();

                // Phase 2: Connect to IRC
                var connection = new IrcConnection(_loggerFactory.CreateLogger<IrcConnection>());
                await using (connection)
                {
                    await connection.ConnectAsync(
                        _config.Server, _config.Port, _config.UseTls, stoppingToken);

                    // Phase 3: Notify plugins and start event dispatchers
                    await _pluginManager.NotifyConnectedAsync(stoppingToken);
                    var eventWriters = _pluginManager.StartEventDispatchers(stoppingToken);

                    // Phase 4: Run the message processor (blocks until disconnect)
                    backoff = InitialBackoffSeconds; // Reset backoff on successful connection
                    await _bot.RunAsync(connection, _config, eventWriters, stoppingToken);
                }
            }
            catch (OperationCanceledException) when (stoppingToken.IsCancellationRequested)
            {
                _logger.LogInformation("Bot shutdown requested");
                break;
            }
            catch (Exception ex)
            {
                _logger.LogError(ex, "Bot disconnected unexpectedly");
            }

            // Cleanup after disconnect
            try
            {
                var disconnectMessage = new IrcMessage(null, null, "DISCONNECT", []);
                var disconnectedEvent = new DisconnectedEvent
                {
                    Timestamp = DateTimeOffset.UtcNow,
                    RawMessage = disconnectMessage
                };

                await _pluginManager.NotifyDisconnectedAsync();
                await _pluginManager.UnloadPluginsAsync();
                _bot.ResetState();
            }
            catch (Exception ex)
            {
                _logger.LogError(ex, "Error during disconnect cleanup");
            }

            if (stoppingToken.IsCancellationRequested) break;

/// <summary>
/// Adds a configuration file source based on the file extension.
/// Supports .json, .yaml/.yml, and .xml formats.
/// </summary>
static void AddConfigFile(IConfigurationBuilder config, string path, bool required)
{
    var extension = Path.GetExtension(path).ToLowerInvariant();

    switch (extension)
    {
        case ".json":
            config.AddJsonFile(path, optional: !required, reloadOnChange: false);
            break;
        case ".yaml" or ".yml":
            config.AddYamlFile(path, optional: !required, reloadOnChange: false);
            break;
        case ".xml":
            config.AddXmlFile(path, optional: !required, reloadOnChange: false);
            break;
        default:
            throw new InvalidOperationException(
                $"Unsupported configuration file format: '{extension}'. " +
                "Supported formats: .json, .yaml, .yml, .xml");
    }
}
