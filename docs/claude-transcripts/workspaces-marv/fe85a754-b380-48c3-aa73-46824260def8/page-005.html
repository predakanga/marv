1	# CS-026: Connection-Scoped DI Services
2	
3	**Source:** GitHub issue #1
4	**Scope:** Core (Plugin API, DI container setup)
5	**Complexity:** Medium-Large
6	**Breaking changes:** Yes — core services move from singleton to scoped registration
7	**Status:** Pending
8	
9	---
10	
11	## Problem
12	
13	Plugins are implicitly scoped to each IRC connection: `MarvBotService`
14	calls `PluginManager.InstantiatePlugins` at the top of every reconnect
15	loop, and `UnloadPluginsAsync` on disconnect. However, the DI services
16	that plugins depend on — `IBot`, `IServerInfo`, `ICapabilityManager`,
17	`IBotStatistics` — are registered as singletons via `AddMarv`. This
18	means:
19	
20	1. **Semantic mismatch.** Core services like `IBot`, `IServerInfo`, and
21	   `ICapabilityManager` are registered as singletons but conceptually
22	   belong to a single connection — the bot calls `ResetState()` on them
23	   between connections. Plugins are torn down and recreated each
24	   connection, so they don't currently hold stale references, but the
25	   singleton lifetime is misleading and prevents the DI container from
26	   enforcing connection boundaries.
27	
28	2. **Scoped services are unusable.** Plugins can call
29	   `services.AddScoped<T>()` in `ConfigureServices`, but because
30	   `PluginActivator` resolves from the root `IServiceProvider`, the
31	   scoped registration is never honoured — the container either throws
32	   (`ValidateScopes`) or silently creates a singleton-lifetime instance.
33	
34	3. **No formal connection boundary.** There is no DI-level signal that
35	   a new connection has begun. Plugins that need per-connection state
36	   must manage it manually in `OnConnectedAsync`/`OnDisconnectedAsync`.
37	
38	## Changes
39	
40	### 1. Create an `IServiceScope` per connection in `MarvBotService`
41	
42	At the start of each iteration of the reconnect loop in
43	`MarvBotService.ExecuteAsync`, create a new `IServiceScope` from the
44	root `IServiceProvider`. Dispose it after disconnect cleanup completes.
45	
46	```csharp
47	while (!stoppingToken.IsCancellationRequested)
48	{
49	    await using var connectionScope = _serviceScopeFactory.CreateAsyncScope();
50	    var scopedProvider = connectionScope.ServiceProvider;
51	
52	    // Use scopedProvider for all resolution within this connection...
53	}
54	```
55	
56	`MarvBotService` should inject `IServiceScopeFactory` instead of (or in
57	addition to) the services it currently resolves at construction time.
58	Services that are now scoped (`IrcBot`, etc.) must be resolved from
59	`scopedProvider` inside the loop rather than captured in the constructor.
60	
61	### 2. Move connection-specific core services to scoped registration
62	
63	In `MarvServiceExtensions.AddMarv`, change these registrations from
64	`AddSingleton` to `AddScoped`:
65	
66	| Service | Interface(s) | Notes |
67	|---|---|---|
68	| `ServerInfo` | `IServerInfo`, concrete | Holds ISUPPORT/005 state |
69	| `CapabilityManager` | `ICapabilityManager`, concrete | Holds negotiated caps |
70	| `IrcBot` | `IBot`, concrete | Holds connection, message loop state |
71	| `BotStatistics` | `IBotStatistics` | Derived from `IrcBot` |
72	
73	| `PluginActivator` | `IPluginActivator` | Used by `MarvPlugin` for handler groups |
74	
75	Services that are genuinely application-lifetime (`PluginManager`,
76	`IReadOnlyList<PluginDescriptor>`, `IHttpClientFactory`,
77	`IOptions<MarvConfiguration>`) remain singletons.
78	
79	The scoped `IrcBot` replaces the current pattern where a single
80	singleton instance calls `ResetState()` between connections. Each scope
81	gets a fresh `IrcBot`, eliminating the need for `ResetState()`.
82	
83	### 3. Update `PluginManager` to accept a scoped `IServiceProvider`
84	
85	`PluginManager` is a singleton, but `InstantiatePlugins` needs to
86	resolve from the connection scope. Change `InstantiatePlugins` (and
87	other per-connection methods) to accept the scoped `IServiceProvider` as
88	a parameter rather than using the one captured at construction:
89	
90	```csharp
91	internal void InstantiatePlugins(
92	    IReadOnlyList<PluginDescriptor> descriptors,
93	    IServiceProvider scopedProvider)
94	{
95	    // Use scopedProvider for ActivatorUtilities.CreateInstance
96	}
97	```
98	
99	This keeps `PluginManager` as a singleton (so it survives reconnects and
100	maintains descriptor state) while ensuring plugins receive scoped
101	dependencies. The `IServiceProvider` currently injected into
102	`PluginManager`'s constructor is no longer needed and should be removed.
103	
104	### 4. Make `PluginActivator` scoped
105	
106	`PluginActivator` implements `IPluginActivator`, which is part of the
107	plugin API — `MarvPlugin` injects it and uses it to create
108	`HandlerGroup` instances. It currently captures `IServiceProvider` in
109	its constructor, but since it's registered as a singleton it always
110	holds the root provider.
111	
112	Change its registration from `AddSingleton` to `AddScoped` so that each
113	connection scope gets a `PluginActivator` backed by the scoped provider.
114	Plugins that inject `IPluginActivator` will then automatically create
115	handler groups with correctly-scoped dependencies.
116	
117	### 5. Update `MarvBotService` constructor and connection loop
118	
119	`MarvBotService` currently injects `IrcBot`, `PluginManager`, etc. as
120	constructor parameters. After this change:
121	
122	- Remove `IrcBot` from the constructor — resolve it from the scoped
123	  provider inside the loop.
124	- Add `IServiceScopeFactory` to the constructor.
125	- `IrcConnection` creation stays as-is (it's a local object, not
126	  DI-managed).
127	- Pass the scoped provider to `PluginManager.InstantiatePlugins`.
128	
129	### 6. Update `Marv.Testing` to create scoped test fixtures
130	
131	`PluginTestHarness` builds an `IServiceProvider` and resolves plugin
132	dependencies from it. Update it to:
133	
134	1. Register `MockBot` and other test doubles as scoped services.
135	2. Create an `IServiceScope` and expose the scoped provider.
136	3. Ensure the scope is disposed when the harness is disposed.
137	
138	This ensures test plugins receive services with the same lifetime
139	semantics as production.
140	
141	### 7. Update `docs/PLUGIN_API.md`
142	
143	Document:
144	
145	- That `IBot`, `IServerInfo`, `ICapabilityManager`, and `IBotStatistics`
146	  are connection-scoped and receive a fresh instance per connection.
147	- That plugins can register scoped services via `ConfigureServices` and
148	  they will be correctly resolved per connection.
149	- That singleton services survive reconnects while scoped services do
150	  not.
151	- Migration guidance for any plugins that stored these services in
152	  static fields or long-lived caches.
153	
154	## Design decisions
155	
156	**Why not make plugins themselves scoped services?** `PluginManager`
157	controls instantiation order based on the dependency graph. The DI
158	container does not guarantee construction order, so letting it manage
159	plugin lifetimes would break the dependency ordering contract.
160	
161	**Why not introduce a new registration point for scoped services?**
162	`IServiceCollection` already supports `AddScoped<T>()`. The only reason
163	it didn't work before was that `PluginActivator` resolved from the root
164	provider. Fixing the provider is sufficient; no API change needed.
165	
166	**Why keep `PluginManager` as a singleton?** It holds the descriptor
167	list and orchestrates the full lifecycle across reconnects. Making it
168	scoped would mean re-discovering plugins on every reconnect, which is
169	unnecessary and expensive.
170	
171	## Testing
172	
173	- **Unit test:** Verify that `IBot` resolved within a scope is a
174	  different instance from one resolved in a second scope.
175	- **Unit test:** Verify that a plugin registering a scoped service via
176	  `ConfigureServices` receives a fresh instance per connection scope.
177	- **Unit test:** Verify that a plugin registering a singleton service
178	  receives the same instance across connection scopes.
179	- **Unit test:** Verify that `PluginManager.InstantiatePlugins` uses the
180	  provided scoped provider, not the root provider.
181	- **Integration test:** Connect, disconnect, reconnect — verify plugins
182	  receive fresh `IBot`/`IServerInfo` instances on the second connection
183	  and that the previous instances are not referenced.
184	- **Marv.Testing:** Verify `PluginTestHarness` creates a scope and that
185	  `MockBot` is resolved as a scoped service.
186	
187	## Impact
188	
189	- **Plugin API:** Breaking change for any plugin-provided singleton
190	  services that inject `IBot`, `IServerInfo`, or other now-scoped
191	  services — the DI container will reject resolving a scoped service
192	  from a singleton. Plugins must change such services to scoped
193	  registration, or use `IServiceScopeFactory` to create their own
194	  scopes. Plugin instances themselves are unaffected since they are
195	  already recreated per connection.
196	- **Plugin DX:** Scoped services now work correctly. Plugins can use the
197	  standard .NET DI lifetime model without surprises.
198	- **Core:** `IrcBot.ResetState()` can be removed since each connection
199	  gets a new instance. This simplifies the bot's internal state
200	  management.
201	- **Risk:** Medium — touches the DI registration, the main service loop,
202	  plugin instantiation, and the test harness. Thorough testing of the
203	  reconnect path is essential.

193	    {

225	    /// <summary>
226	    /// Computes the Levenshtein edit distance between two strings.
227	    /// </summary>
228	    private static int LevenshteinDistance(string a, string b)
229	    {
230	        if (a.Length == 0) return b.Length;
231	        if (b.Length == 0) return a.Length;
232	
233	        var prev = new int[b.Length + 1];
234	        var curr = new int[b.Length + 1];
235	
236	        for (var j = 0; j <= b.Length; j++)
237	            prev[j] = j;
238	
239	        for (var i = 1; i <= a.Length; i++)
240	        {
241	            curr[0] = i;
242	            for (var j = 1; j <= b.Length; j++)
243	            {
244	                var cost = a[i - 1] == b[j - 1] ? 0 : 1;
245	                curr[j] = Math.Min(
246	                    Math.Min(curr[j - 1] + 1, prev[j] + 1),
247	                    prev[j - 1] + cost);
248	            }
249	
250	            (prev, curr) = (curr, prev);
251	        }
252	
253	        return prev[b.Length];
254	    }

/// <summary>
/// Hosted service that orchestrates the bot's lifecycle: plugin loading,
/// IRC connection, message processing, reconnection, and graceful shutdown.
/// Each connection iteration creates a new DI scope so that connection-scoped
/// services (IrcBot, ServerInfo, CapabilityManager, etc.) receive fresh instances.
/// </summary>
internal sealed class MarvBotService : BackgroundService
{
    private readonly ILogger<MarvBotService> _logger;
    private readonly IServiceScopeFactory _scopeFactory;
    private readonly PluginManager _pluginManager;
    private readonly IReadOnlyList<PluginDescriptor> _descriptors;
    private readonly MarvConfiguration _config;
    private readonly ILoggerFactory _loggerFactory;

    // Reconnection backoff
    private const int InitialBackoffSeconds = 5;
    private const int MaxBackoffSeconds = 300;

    public MarvBotService(
        ILogger<MarvBotService> logger,
        IServiceScopeFactory scopeFactory,
        PluginManager pluginManager,
        IReadOnlyList<PluginDescriptor> descriptors,
        IOptions<MarvConfiguration> config,
        ILoggerFactory loggerFactory)
    {
        _logger = logger;
        _scopeFactory = scopeFactory;
        _pluginManager = pluginManager;
        _descriptors = descriptors;
        _config = config.Value;
        _loggerFactory = loggerFactory;
    }

    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        var backoff = InitialBackoffSeconds;

        while (!stoppingToken.IsCancellationRequested)
        {
            await using var connectionScope = _scopeFactory.CreateAsyncScope();
            var scopedProvider = connectionScope.ServiceProvider;

            try
            {
                // Phase 1: Instantiate and load plugins (using scoped provider)
                _pluginManager.InstantiatePlugins(_descriptors, scopedProvider);
                await _pluginManager.LoadPluginsAsync(stoppingToken);
                _pluginManager.LogDiagnostics();

                // Phase 2: Resolve the scoped bot and connect to IRC
                var bot = scopedProvider.GetRequiredService<IrcBot>();
                var connection = new IrcConnection(
                    _loggerFactory.CreateLogger<IrcConnection>(),
                    _config.RateLimitEnabled,
                    _config.RateLimitBurst,
                    _config.RateLimitRefillRate);
                await using (connection)
                {
                    await connection.ConnectAsync(
                        _config.Server, _config.Port, _config.UseTls, stoppingToken,
                        _config.TlsSkipCertificateValidation, _config.TlsCaCertFile);

                    // Phase 3: Notify plugins and start event dispatchers
                    await _pluginManager.NotifyConnectedAsync(stoppingToken);
                    var eventWriters = _pluginManager.StartEventDispatchers(stoppingToken);

                    // Phase 4: Run the message processor (blocks until disconnect)
                    backoff = InitialBackoffSeconds; // Reset backoff on successful connection
                    await bot.RunAsync(connection, _config, eventWriters, stoppingToken);
                }
            }
            catch (OperationCanceledException) when (stoppingToken.IsCancellationRequested)
            {
                _logger.LogInformation("Bot shutdown requested");
                break;
            }
            catch (Exception ex)
            {
                _logger.LogError(ex, "Bot disconnected unexpectedly");
            }

            // Cleanup after disconnect
            try
            {
                await _pluginManager.NotifyDisconnectedAsync();
                await _pluginManager.UnloadPluginsAsync();
            }
            catch (Exception ex)
            {
                _logger.LogError(ex, "Error during disconnect cleanup");
            }

            if (stoppingToken.IsCancellationRequested) break;

            // Exponential backoff before reconnection
            _logger.LogInformation("Reconnecting in {Seconds} seconds...", backoff);
            try
            {
                await Task.Delay(TimeSpan.FromSeconds(backoff), stoppingToken);
            }
            catch (OperationCanceledException)
            {
                break;
            }

            backoff = Math.Min(backoff * 2, MaxBackoffSeconds);
        }

        // Final cleanup
        try
        {
            await _pluginManager.NotifyDisconnectedAsync();
            await _pluginManager.UnloadPluginsAsync();
        }
        catch (Exception ex)
        {
            _logger.LogError(ex, "Error during final shutdown cleanup");
        }

        _logger.LogInformation("Bot stopped");
    }

/// <see cref="IPluginActivator"/> backed by a connection-scoped

/// <para>
/// Services are registered as scoped to match the production lifetime semantics,
/// where core services are scoped to each IRC connection.
/// </para>
/// <para>

/// </para>
/// </remarks>

/// <code>
/// using var harness = PluginTestHarness&lt;GreetPlugin&gt;.Create();
/// await harness.LoadAsync();

/// </code>

/// <typeparam name="TPlugin">The concrete plugin type to test.</typeparam>
public sealed class PluginTestHarness<TPlugin> : IDisposable where TPlugin : MarvPlugin
{
    private readonly ServiceProvider _rootProvider;
    private readonly IServiceScope _scope;

    /// <summary>The plugin instance under test.</summary>
    public TPlugin Plugin { get; }

    /// <summary>The mocked <see cref="IBot"/> injected into the plugin.</summary>
    public IBot Bot { get; }

    /// <summary>The scoped service provider backing the plugin activator.</summary>
    public IServiceProvider Services { get; }

    private PluginTestHarness(TPlugin plugin, IBot bot, ServiceProvider rootProvider, IServiceScope scope)
    {
        Plugin = plugin;
        Bot = bot;
        _rootProvider = rootProvider;
        _scope = scope;
        Services = scope.ServiceProvider;
    }

    /// <summary>
    /// Creates a new test harness for the specified plugin type.
    /// </summary>
    /// <param name="configureServices">
    /// Optional callback to register additional services (e.g. configuration objects,
    /// inter-plugin service mocks) before the plugin is constructed.
    /// </param>
    /// <param name="bot">
    /// Optional custom <see cref="IBot"/> mock. If null, <see cref="MockBot.Create()"/>
    /// is used.
    /// </param>
    public static PluginTestHarness<TPlugin> Create(
        Action<IServiceCollection>? configureServices = null,
        IBot? bot = null)
    {
        bot ??= MockBot.Create();

        var services = new ServiceCollection();
        services.AddScoped<IBot>(_ => bot);
        services.AddSingleton<ILoggerFactory>(NullLoggerFactory.Instance);
        services.AddScoped<IPluginActivator, TestPluginActivator>();

        configureServices?.Invoke(services);

        var rootProvider = services.BuildServiceProvider();
        var scope = rootProvider.CreateScope();
        var scopedProvider = scope.ServiceProvider;

        var activator = scopedProvider.GetRequiredService<IPluginActivator>();
        var plugin = activator.CreateInstance<TPlugin>();
        return new PluginTestHarness<TPlugin>(plugin, bot, rootProvider, scope);
    }

    /// Call this explicitly after any additional setup.
    /// </summary>
    public Task LoadAsync(CancellationToken ct = default) =>
        Plugin.OnLoadAsync(ct);

    /// Calls <see cref="MarvPlugin.OnConnectedAsync"/> on the plugin.
    /// </summary>
    public Task ConnectedAsync(CancellationToken ct = default) =>
        Plugin.OnConnectedAsync(ct);

    /// <summary>
    /// Dispatches an event to the plugin's handler pipeline.
    /// </summary>
    public Task HandleEventAsync(Core.Events.MarvEvent evt, CancellationToken ct = default) =>

## 9. Services

### Service lifetimes

Core services like `IBot`, `IServerInfo`, `ICapabilityManager`,
`IBotStatistics`, and `IPluginActivator` are **connection-scoped** — a fresh
instance is created for each IRC connection and disposed on disconnect.
Plugins are also recreated per connection, so they always receive the
current connection's services.

Plugins can register services with any standard DI lifetime:

| Lifetime | `ConfigureServices` call | Behaviour |
|---|---|---|
| **Scoped** | `services.AddScoped<T, TImpl>()` | Fresh instance per connection — matches plugin lifetime |
| **Singleton** | `services.AddSingleton<T, TImpl>()` | Survives reconnects — use for cross-connection state (caches, metrics) |
| **Transient** | `services.AddTransient<T, TImpl>()` | New instance per resolution |

> **Note:** Singleton services must not capture scoped services (e.g. `IBot`)
> in their constructors. The DI container will reject this. If a singleton
> needs access to connection-scoped services, inject `IServiceScopeFactory`
> and create a scope on demand.
