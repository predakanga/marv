1	# CS-003: Handler Dispatch Filters
2	
3	**Source:** `downstream_suggestions/improvements.md` §1
4	**Scope:** Marv.Core
5	**Complexity:** Small
6	**Breaking changes:** None (additive properties on existing attributes)
7	
8	---
9	
10	## Problem
11	
12	Nearly every command and regex handler begins with a channel/DM guard:
13	
14	```csharp
15	if (ctx.IsDirect) return;          // channel-only handler
16	if (!ctx.IsDirect) return;         // DM-only handler
17	if (ctx.Channel?.Name != "#ops")   // channel-specific handler
18	    return;
19	```
20	
21	This is repetitive boilerplate that the framework can handle declaratively.
22	
23	## Changes
24	
25	### 1. Add filter properties to `OnCommandAttribute`
26	
27	```csharp
28	[AttributeUsage(AttributeTargets.Method, AllowMultiple = true, Inherited = false)]
29	public sealed class OnCommandAttribute(string command) : Attribute
30	{
31	    public string Command { get; } = command;
32	
33	    /// <summary>
34	    /// If true, handler only fires for channel messages (skips DMs).
35	    /// </summary>
36	    public bool ChannelOnly { get; init; }
37	
38	    /// <summary>
39	    /// If true, handler only fires for direct/private messages (skips channel).
40	    /// </summary>
41	    public bool DirectOnly { get; init; }
42	
43	    /// <summary>
44	    /// If set, handler only fires when the message is in this channel.
45	    /// Case-insensitive comparison using the server's case mapping.
46	    /// </summary>
47	    public string? Channel { get; init; }
48	}
49	```
50	
51	### 2. Add the same properties to `OnRegexAttribute`
52	
53	Same three properties: `ChannelOnly`, `DirectOnly`, `Channel`.
54	
55	### 3. Apply filters in dispatch
56	
57	**`MarvPlugin.DispatchCommandHandlers`** — after matching the command name
58	and before creating the `CommandContext`, check the filter properties:
59	
60	```csharp
61	if (handler.ChannelOnly && msgEvt.Channel is null)
62	    continue;
63	if (handler.DirectOnly && msgEvt.Channel is not null)
64	    continue;
65	if (handler.Channel is not null
66	    && !string.Equals(msgEvt.Channel?.Name, handler.Channel,
67	        StringComparison.OrdinalIgnoreCase))
68	    continue;
69	```
70	
71	Same logic in `DispatchRegexHandlers`.
72	
73	### 4. Store filter values in registration records
74	
75	The existing `CommandRegistration` and `RegexRegistration` records need the
76	filter values copied from the attribute at discovery time:
77	
78	```csharp
79	private sealed record CommandRegistration(
80	    object Target, MethodInfo Method, string Command,
81	    bool ChannelOnly, bool DirectOnly, string? Channel);
82	```
83	
84	### 5. Validation at discovery time
85	
86	Warn (via logger) if both `ChannelOnly` and `DirectOnly` are set on the same
87	attribute — the handler would never fire. Similarly, warn if `Channel` is set
88	alongside `DirectOnly` (contradictory).
89	
90	## Usage
91	
92	```csharp
93	[OnCommand("ban", ChannelOnly = true)]
94	public async Task HandleBan(CommandContext ctx, CancellationToken ct) { ... }
95	
96	[OnCommand("identify", DirectOnly = true)]
97	public async Task HandleIdentify(CommandContext ctx, CancellationToken ct) { ... }
98	
99	[OnRegex(@"https?://\S+", Channel = "#links")]
100	public async Task HandleUrl(RegexMatchContext ctx, CancellationToken ct) { ... }
101	```
102	
103	## Case mapping consideration
104	
105	The `Channel` filter should ideally use the server's case mapping (via
106	`IServerInfo.CaseMapping`) for comparison rather than
107	`StringComparison.OrdinalIgnoreCase`. However, at handler discovery time the
108	server connection may not be established. Two options:
109	
110	1. **Simple:** Use `OrdinalIgnoreCase`. Works for ASCII channel names (the
111	   vast majority). Document the limitation.
112	2. **Correct:** Defer comparison to dispatch time, reading case mapping from
113	   `Bot.ServerInfo`. Slightly more complex but handles edge cases like
114	   `{|}` ↔ `[|\]` mapping.
115	
116	**Recommendation:** Start with option 1. The case mapping edge cases affect
117	channels with `{|}~` characters, which are rare. Can be refined later.
118	
119	## Impact
120	
121	- **Plugin API:** Additive properties on existing attributes. No existing
122	  code changes needed — default values (`false`/`null`) preserve current
123	  behavior.
124	- **Tests:** Add unit tests for each filter combination.
