# Bot Mode Detection and Activation in IRCv3

## Activation Mechanism

Bot mode is activated through a **user mode**, not a CAP capability. The specification states: "Servers publishing the `BOT` ISUPPORT token let clients mark themselves as bots by setting a user mode."

The exact mode character is communicated via ISUPPORT. In the provided example, the server advertises `BOT=b`, and the bot then executes `MODE robodan +b` to enable bot mode on itself.

## Detection Methods

Bot status is detected through three mechanisms:

1. **ISUPPORT Token (`BOT=`)**: Servers announce support and specify the mode character used (e.g., `BOT=B` or `BOT=b`)

2. **WHOIS Response**: "When a client is marked as a bot, they are given a special numeric as part of their `WHOIS` response" — specifically the `RPL_WHOISBOT` (335) numeric

3. **WHO Flags**: The bot mode character appears in `RPL_WHOREPLY` responses alongside `H|G` flags

4. **Message Tag**: "The `bot` tag indicates that the given user is a bot" and should be included on commands from bots when clients have requested the `message-tags` capability

There is **no CAP requirement** for basic bot mode; the `message-tags` capability only applies to the optional tag feature.
