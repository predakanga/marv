There's a bug with command-line options and MarvConfiguration - when no CLI arguments are provided, the boolean options are set to false in the configuration regardless of what the config file has set.

3 bash · 2 read · 2 edit

Found the bug. On line 86-89, bool properties create Option<bool> which always has a default value of false in System.CommandLine. Unlike nullable types (int?, string?), result.GetResult() returns non-null even when the flag isn't provided, so the override always gets written as "False" — clobbering whatever the config file set.

The fix is to use Option<bool?> so that "not provided" is distinguishable from "explicitly set to false", matching how other scalar types work.
